# Support

Use [GitHub Issues](https://github.com/ch4570/bandit/issues) for installation problems, incorrect instructions, reproducible planning failures, and feature requests. English and Korean reports are welcome.

For an installation issue, include the BANDIT version, operating system, Node.js and npm versions, exact command, and relevant output. For a skill behavior issue, include the host and model when known, the exact skill command used and how it was loaded, the requested task, a sanitized input, the actual output, and the expected product rule.

Keep account credentials, private customer records, unpublished business documents, and local personal paths out of public reports. A small fictional reproduction is enough to explain many problems. Do not paste an entire agent conversation when a short excerpt demonstrates the issue.

If an earlier command set still appears, run the 0.4.0 command in [Install](INSTALL.md#upgrade-from-02-or-03) and start a new agent session. The current tasks are research, MVP scope, specification writing or rewriting, and review. For a migration conflict, preserve the old customized skill before moving it outside discovery and retrying.

Installation success, host discovery, and task quality are separate checks. [Install](INSTALL.md) covers folder and invocation problems; [Validation](VALIDATION.md) records executed checks; [Evaluation](evals/README.md) explains how output quality is assessed.

BANDIT is an instruction package. Model availability, billing, and host tool permissions are managed by the service running your agent. Reports about those services should go to their respective support channels.
