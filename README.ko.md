# BANDIT · 밴딧

**생각은 대담하게. 기획은 빈틈없이.**

[English](README.md) · [설치](INSTALL.md) · [스킬 종류와 사용법](#skill-catalog) · [예제](examples/README.md) · [v0.2.0](https://github.com/ch4570/bandit/releases/tag/v0.2.0)

밴딧은 카우보이 모자를 쓴 기획 파트너입니다. 무기는 연필, 손에는 다음 결정을 위한 지도. 막 떠오른 아이디어도, 기능이 너무 많은 MVP도, 어딘가 빠진 기획서도 함께 실행할 계획으로 정리합니다.

## 한 줄로 합류

**작업할 프로젝트 폴더에서** 실행하세요.

```sh
npx --yes https://github.com/ch4570/bandit/releases/download/v0.2.0/bandit.tgz
```

설치한 뒤 에이전트에 바로 요청하면 됩니다.

```text
$bandit 이 아이디어를 2주 안에 만들 MVP로 기획해줘.
처음 쓰는 사람이 목적을 끝낼 최소 범위를 추천하고,
뺄 기능과 그 이유까지 기존 기획서에 정리해줘.
```

**Node.js 22 이상과 npm**만 있으면 됩니다. `.agents/skills/bandit/`에 스킬 전체를 설치합니다. Git·저장소 복제·Python 설정은 필요 없습니다. [다른 설치 방법](INSTALL.md).

npm 레지스트리 등록은 추후 진행합니다. 위 명령은 지금 GitHub에서 직접 설치합니다. 에이전트가 `$bandit`을 찾지 못하면 `.agents/skills/bandit/SKILL.md`를 읽고 적용하라고 요청하세요. 필요하면 새 에이전트 세션을 여세요.

## 스킬 종류와 사용법

**BANDIT 스킬 하나에 아래 5가지 기획 모드가 들어 있습니다.** 모두 `$bandit` 뒤에 원하는 작업을 적어 사용합니다. 작업에 맞는 모드를 자동으로 선택하므로 이름을 외우거나 순서대로 실행할 필요 없습니다.

| 종류 | 이럴 때 사용하세요 | 받는 결과 |
| --- | --- | --- |
| [조사 · Research](#research) | 고객 문제·경쟁 서비스·사업 가정을 살피거나 실험을 설계할 때 | 출처가 있는 근거, 미확인 가정, 다음 검증 실험 |
| [결정 · Decide](#decide) | MVP 범위를 줄이거나 기능 우선순위·대안을 고를 때 | 권고안, 포함·보류·제외 범위, 선택 이유와 재검토 조건 |
| [명세 · Specify](#specify) | 아이디어를 PRD·사용자 흐름·개발 요구사항으로 구체화할 때 | 역할·권한·상태·예외 규칙과 수용 시나리오 |
| [검토 · Review](#review) | 기존 기획서의 누락·모순·근거 부족을 찾을 때 | 위치와 영향이 명확한 지적 사항, 우선순위, 수정 제안 |
| [변경 · Update](#update) | 가격·정책·제품 방향을 바꾸거나 새 실험 결과를 반영할 때 | 관련 기획 수정, 변경 영향, 보존할 과거 근거와 재검증 항목 |

아래 예시의 아이디어와 문서 경로를 본인 프로젝트에 맞게 바꿔서 요청하세요. 기존 자료, 일정·인원 같은 제약, 원하는 결과물을 함께 주면 좋습니다.

<a id="research"></a>

### 1. 조사 · Research

고객 문제와 현재 대안, 경쟁 서비스, 가격·수익 가정을 조사하고 무엇부터 검증할지 정합니다.

```text
$bandit 프리랜서가 고객의 변경 요청을 관리하는 앱을 기획 중이야.
고객 문제와 현재 대안을 조사하고, 사실과 가정을 구분해줘.
인터뷰는 아직 없어. 개발 전에 수요를 확인할 작은 실험 하나와
그 결과에 따라 진행·수정·중단을 판단할 기준을 제안해줘.
```

**결과:** 근거 요약, 아직 확인되지 않은 가정, 실험 대상·방법·판단 기준. 실시간 검색은 사용 중인 에이전트의 도구가 필요하며, 검색할 수 없으면 제공된 자료와 조사 계획을 바탕으로 답합니다. [조사 동작 지침](skills/bandit/references/research.md)

<a id="decide"></a>

### 2. 결정 · Decide

일정과 인원에 맞춰 MVP 범위를 정하고, 기능 우선순위와 수동 대안을 비교합니다.

```text
$bandit docs/PRD.md를 1인 개발, 2주 MVP 범위로 줄여줘.
고객이 변경 요청을 확인하고 수락하는 흐름은 끝까지 유지해.
포함·보류·제외할 기능과 이유, 수동으로 대신할 부분을 정리하고
기존 기획서에 반영해줘. 작업량이 불확실한 부분은 가정으로 표시해줘.
```

**결과:** 최소 완결 흐름, 범위 결정표, 의존성과 작업량 가정, 나중에 결정을 다시 볼 조건. [결정 동작 지침](skills/bandit/references/decisions.md)

<a id="specify"></a>

### 3. 명세 · Specify

아이디어나 채택한 결정을 개발에 전달할 PRD와 구체적인 동작 규칙으로 정리합니다.

```text
$bandit 5명이 함께 쓰는 일정 투표 기능을 개발 명세로 써줘.
동률, 미응답, 자기 표 변경, 확정 후 재논의 규칙을 포함해.
역할·권한·상태 전이·예외와 테스트 가능한 수용 시나리오를 정리하고,
정해지지 않은 규칙은 추천 초안으로 표시해서 docs/PRD.md에 작성해줘.
```

**결과:** 사용자 흐름, 도메인 규칙, 실패·복구 동작, 수용 시나리오와 남은 결정. 기존 PRD가 있으면 그 구조를 이어 씁니다. [명세 동작 지침](skills/bandit/references/specification.md)

<a id="review"></a>

### 4. 검토 · Review

기존 기획서를 읽고 구현이나 제품 판단을 달라지게 만들 누락·모순·근거 부족을 찾습니다.

```text
$bandit docs/PRD.md를 검토해줘. 파일은 수정하지 마.
핵심 사용 흐름, 권한, 예외 처리, 수용 기준 사이의 누락과 모순을 찾아줘.
각 지적에 문서 위치, 발생 상황, 영향, 수정 제안을 붙이고
먼저 해결할 것부터 정리해줘.
```

**결과:** 원본을 유지한 검토 의견과 수정 제안. 문서 검토에서 확인한 내용과 실제 제품 실행으로 확인한 내용을 구분합니다. [검토 동작 지침](skills/bandit/references/review.md)

<a id="update"></a>

### 5. 변경 · Update

가격·권한·MVP 범위 등의 결정이 바뀌거나 새 실험 결과가 생겼을 때 관련 기획을 갱신합니다.

```text
$bandit 유료 개인 플랜을 무료 공유 작업공간으로 바꾸기로 했어.
docs/PRD.md에서 가격·권한·첫 사용 흐름·지표·다음 실험에 미치는 영향을
찾아 반영해줘. 이전 유료 파일럿 결과는 당시 가격과 조건을 붙여 보존하고,
새 조건에서 다시 확인해야 할 항목도 정리해줘.
```

**결과:** 변경 전후 요약, 관련 요구사항 수정, 과거 근거의 적용 범위와 재검증 항목. [변경 동작 지침](skills/bandit/references/changes.md)

다섯 모드는 공통으로 [근거와 결정 관리 원칙](skills/bandit/references/evidence-and-decisions.md)을 사용합니다. 새 기획서를 시작할 때는 선택적으로 [기획서 템플릿](skills/bandit/assets/plan-template.md)을 참고할 수 있습니다. 더 많은 예시는 [한국어 사용법](docs/usage.ko.md)에 있습니다.

## 과감하게 제안하고, 근거는 정확하게

밴딧은 짧고 분명하게 말하며, 결정을 위임받으면 이유 있는 권고안을 냅니다. 서부 캐릭터는 소개와 시각 요소에 담고, 실제 기획서는 자연스럽고 전문적인 문장으로 씁니다.

사실과 가정, 제안과 확정, 계획한 검증과 실제 결과를 구분합니다. 기능 이름만 적지 않고 누가 언제 무엇을 할 수 있는지 구체화합니다. 기존 기획서를 이어 쓰며, 작은 결정에 새 문서 체계를 요구하지 않습니다.

이 컴퓨터의 **모든 Codex 프로젝트**에서 쓰려면:

```sh
npx --yes https://github.com/ch4570/bandit/releases/download/v0.2.0/bandit.tgz --global
```

밴딧은 스킬과 설치 도구를 제공합니다. 모델·검색·파일 접근은 사용 중인 에이전트가 제공하며, 해당 서비스의 권한과 사용량이 적용됩니다.
