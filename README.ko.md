# BANDIT · 밴딧

**생각은 대담하게. 기획은 빈틈없이.**

[English](README.md) · [설치](INSTALL.md) · [스킬 명령어와 사용법](#skill-catalog) · [예제](examples/README.md) · [v0.4.0](https://github.com/ch4570/bandit/releases/tag/v0.4.0)

밴딧은 카우보이 모자를 쓴 기획 파트너입니다. 무기는 연필, 손에는 다음 결정을 위한 지도. 막 떠오른 아이디어도, 기능이 너무 많은 MVP도, 어딘가 빠진 기획서도 함께 실행할 계획으로 정리합니다.

## 한 줄로 합류

**작업할 프로젝트 폴더에서** 실행하세요.

```sh
npx --yes https://github.com/ch4570/bandit/releases/download/v0.4.0/bandit.tgz
```

설치한 뒤 에이전트에 바로 요청하면 됩니다.

```text
$bandit-scope 이 아이디어를 2주 안에 만들 MVP로 기획해줘.
처음 쓰는 사람이 목적을 끝낼 최소 범위를 추천하고,
뺄 기능과 그 이유까지 기존 기획서에 정리해줘.
```

**Node.js 22 이상과 npm**만 있으면 됩니다. `.agents/skills/`에 **전문 스킬 4개와 통합 스킬 1개**를 한 번에 설치합니다. Git·저장소 복제·Python 설정은 필요 없습니다. [다른 설치 방법](INSTALL.md).

**0.2 또는 0.3을 사용 중이라면** 같은 프로젝트에서 위 0.4.0 설치 명령을 실행한 뒤 새 에이전트 세션을 여세요. 기존 `--global`이나 경로 옵션은 그대로 붙이세요. [업그레이드 안내](INSTALL.md#upgrade-from-02-or-03)

npm 레지스트리 등록은 추후 진행합니다. 위 명령은 지금 GitHub에서 직접 설치합니다. 에이전트가 `$bandit-scope`를 찾지 못하면 `.agents/skills/bandit-scope/SKILL.md`를 읽고 적용하라고 요청하세요. 필요하면 새 에이전트 세션을 여세요.

## 스킬 명령어와 사용법

**각 전문 스킬을 별도 명령어로 호출할 수 있습니다.** 필요한 명령어 뒤에 작업을 적으세요. 한 번 설치하면 아래 5개가 모두 추가되며, 각각 독립된 스킬 지침을 갖습니다.

| 명령어 | 이럴 때 사용하세요 | 받는 결과 |
| --- | --- | --- |
| [`$bandit-research`](#research) | 고객 문제·경쟁 서비스·수요를 조사하거나 실험을 설계할 때 | 출처가 있는 근거, 미확인 가정, 다음 검증 실험 |
| [`$bandit-scope`](#scope) | MVP 범위와 기능 우선순위를 일정·인원에 맞춰 정할 때 | 포함·보류·제외 범위, 선택 이유, 핵심 의존성 |
| [`$bandit-specify`](#specify) | 기획서를 새로 쓰거나 기존 기획서를 새 방향에 맞춰 다시 쓸 때 | 일관된 PRD, 역할·상태·예외 규칙, 수용 시나리오와 보존할 근거 |
| [`$bandit-review`](#review) | 기존 기획서의 누락·모순·근거 부족을 검토할 때 | 위치와 영향이 명확한 지적 사항, 우선순위, 수정 제안 |
| [`$bandit`](#general-planning) | 여러 기획 작업을 함께 맡기거나 진행 방식을 위임할 때 | 요청 전체에 맞춘 기획안과 권고 |

아래 예시의 아이디어와 문서 경로를 본인 프로젝트에 맞게 바꿔서 요청하세요. 기존 자료, 일정·인원 같은 제약, 원하는 결과물을 함께 주면 좋습니다.

<a id="research"></a>

### 1. 조사 · Research

고객 문제와 현재 대안, 경쟁 서비스, 가격·수익 가정을 조사하고 무엇부터 검증할지 정합니다.

```text
$bandit-research 프리랜서가 고객의 변경 요청을 관리하는 앱을 기획 중이야.
고객 문제와 현재 대안을 조사하고, 사실과 가정을 구분해줘.
인터뷰는 아직 없어. 개발 전에 수요를 확인할 작은 실험 하나와
그 결과에 따라 진행·수정·중단을 판단할 기준을 제안해줘.
```

**결과:** 근거 요약, 아직 확인되지 않은 가정, 실험 대상·방법·판단 기준. 실시간 검색은 사용 중인 에이전트의 도구가 필요하며, 검색할 수 없으면 제공된 자료와 조사 계획을 바탕으로 답합니다. [조사 동작 지침](skills/bandit-research/SKILL.md)

<a id="scope"></a>

### 2. MVP 범위 · Scope

일정과 인원에 맞춰 MVP 범위를 정하고, 기능 우선순위와 수동 대안을 비교합니다.

```text
$bandit-scope docs/PRD.md를 1인 개발, 2주 MVP 범위로 줄여줘.
고객이 변경 요청을 확인하고 수락하는 흐름은 끝까지 유지해.
포함·보류·제외할 기능과 이유, 수동으로 대신할 부분을 정리하고
기존 기획서에 반영해줘. 작업량이 불확실한 부분은 가정으로 표시해줘.
```

**결과:** 최소 완결 흐름, 범위 결정표, 의존성과 작업량 가정, 나중에 결정을 다시 볼 조건. [범위 설정 지침](skills/bandit-scope/SKILL.md)

<a id="specify"></a>

### 3. 기획서 작성·재작성 · Specify

기획서를 새로 쓰거나, 이미 있는 기획서를 새 방향에 맞춰 다시 작성합니다.

새 기획서를 만들 때:

```text
$bandit-specify 5명이 함께 쓰는 일정 투표 기능을 개발 명세로 써줘.
동률, 미응답, 자기 표 변경, 확정 후 재논의 규칙을 포함해.
역할·권한·상태 전이·예외와 테스트 가능한 수용 시나리오를 정리하고,
정해지지 않은 규칙은 추천 초안으로 표시해서 docs/PRD.md에 작성해줘.
```

기존 기획서의 방향이 바뀌었을 때:

```text
$bandit-specify 유료 개인 플랜을 무료 공유 작업공간으로 바꾸기로 했어.
docs/PRD.md를 새 방향에 맞춰 다시 써줘. 필요하면 문서 구조와 기존 규칙도
재구성하고, 권한·첫 사용 흐름·지표·수용 기준을 일관되게 맞춰줘.
이전 파일럿 결과는 당시 가격과 조건을 붙여 보존해줘.
```

**결과:** 새 PRD 또는 재작성한 PRD, 사용자 흐름, 도메인 규칙, 실패·복구 동작과 수용 시나리오. 필요한 범위에서 문서 구조와 규칙을 바꾸며, 과거 관측 결과의 의미는 유지합니다. [기획서 작성 지침](skills/bandit-specify/SKILL.md)

<a id="review"></a>

### 4. 검토 · Review

기존 기획서를 읽고 구현이나 제품 판단을 달라지게 만들 누락·모순·근거 부족을 찾습니다.

```text
$bandit-review docs/PRD.md를 검토해줘. 파일은 수정하지 마.
핵심 사용 흐름, 권한, 예외 처리, 수용 기준 사이의 누락과 모순을 찾아줘.
각 지적에 문서 위치, 발생 상황, 영향, 수정 제안을 붙이고
먼저 해결할 것부터 정리해줘.
```

**결과:** 원본을 유지한 검토 의견과 수정 제안. 문서 검토에서 확인한 내용과 실제 제품 실행으로 확인한 내용을 구분합니다. [검토 동작 지침](skills/bandit-review/SKILL.md)

<a id="general-planning"></a>

### 통합 기획 · `$bandit`

여러 작업을 함께 맡기고 싶으면 기존 `$bandit` 명령어를 사용하세요.

```text
$bandit 이 앱 아이디어의 근거를 검토하고, 2주 MVP 범위를 추천한 다음
선택한 범위를 개발 명세로 정리해줘. 확인되지 않은 부분은 가정으로 표시해줘.
```

요청에 맞는 기획 작업을 선택해 이어갑니다. [통합 스킬 지침](skills/bandit/SKILL.md)

네 전문 스킬은 공통으로 [근거와 결정 관리 원칙](skills/bandit/references/evidence-and-decisions.md)을 사용합니다. 새 기획서를 시작할 때는 선택적으로 [기획서 템플릿](skills/bandit/assets/plan-template.md)을 참고할 수 있습니다. 더 많은 예시는 [한국어 사용법](docs/usage.ko.md)에 있습니다.

## 출시 예정: 제품의 약속부터 수익 구조까지 연결

**현재 브랜치의 미출시 지침입니다.** 위 v0.4.0 설치 명령은 공개된 릴리스를 설치하며, 새 제품 여정 지침은 포함하지 않습니다.

이 브랜치는 기존 5개 명령어에서 조사 → 제품 기획 → 마케팅 → 제품 설계 전달 → 비즈니스 모델(BM)을 연결합니다. 조사로 고객과 문제를 확인하고, 범위 결정으로 제공할 결과를 정합니다. 마케팅은 그 약속을 설명하고, 제품 설계는 사용자가 결과에 도달하는 흐름을 구체화합니다. BM은 누가 비용을 내고 제공에 얼마가 드는지 살핍니다. 뒤에서 확인한 가격·처리량 제약에 따라 앞선 약속과 흐름을 다시 조정할 수 있습니다.

여러 단계를 함께 요청할 때는 `$bandit`을 사용하세요. 다음은 가상 상황의 요청 예시이며, 실제 제품 평가 결과가 아닙니다.

```text
$bandit 제공된 자료로 프리랜서용 변경 요청 승인 서비스의 가능성을 검토해줘.
1인 개발 2주 MVP를 추천하고, 마케팅 기획안, 제품 흐름·콘텐츠·텍스트
와이어프레임, 비즈니스 모델을 연결해줘. 가격·비용·처리량 가정을 명시하고,
고객·약속·제공 조건을 일관되게 맞춰줘. 제안한 선택과 미확인 주장을
구분하고, 다음 판단에 필요한 실험을 제안해줘.
```

근거와 제품 범위, 홍보 문구 초안과 채널 실험, 사용자 흐름과 상태, 수익·비용 가정을 연결한 전달 자료를 기대할 수 있습니다. 여기서 제품 설계는 다음 담당자가 사용할 흐름·콘텐츠·와이어프레임 기획안입니다. 화면을 렌더링하거나 사용성 테스트를 마쳤다는 뜻은 아닙니다. 기획 요청만으로 게시·고객 연락·지출·구현을 실행하지 않습니다.

일부만 필요하면 `$bandit-research`로 제공 조건을 뒷받침할 근거를 조사하고, `$bandit-scope`로 제공 범위를 정하세요. UX·사업 기획안은 `$bandit-specify`, 문서 간 일관성 검토는 `$bandit-review`에 맡길 수 있습니다. [출시 예정 사용 예시](docs/usage.ko.md#upcoming-product-journey)와 [제품 여정 지침](skills/bandit/references/product-journey.md)을 참고하세요. 좁은 요청을 전체 제품 전략으로 확대하지 않습니다.

## 과감하게 제안하고, 근거는 정확하게

밴딧은 짧고 분명하게 말하며, 결정을 위임받으면 이유 있는 권고안을 냅니다. 서부 캐릭터는 소개와 시각 요소에 담고, 실제 기획서는 자연스럽고 전문적인 문장으로 씁니다.

사실과 가정, 제안과 확정, 계획한 검증과 실제 결과를 구분합니다. 기능 이름만 적지 않고 누가 언제 무엇을 할 수 있는지 구체화합니다. 기존 기획서를 이어 쓰며, 작은 결정에 새 문서 체계를 요구하지 않습니다.

이 컴퓨터의 **모든 Codex 프로젝트**에서 쓰려면:

```sh
npx --yes https://github.com/ch4570/bandit/releases/download/v0.4.0/bandit.tgz --global
```

밴딧은 다섯 스킬과 설치 도구를 제공합니다. 모델·검색·파일 접근은 사용 중인 에이전트가 제공하며, 해당 서비스의 권한과 사용량이 적용됩니다.
