# GatherTrip — 개발 인계용 MVP 명세

**범위:** 개발자 1명, 2주. 4–8명 여행 그룹이 로그인 없이 참여해 숙소와 출발일을 각각 투표하고, 주최자가 각 최종안을 확정한다.

**근거와 결정 상태:** `input/request.md`와 `input/brief.md`의 창업자 선택 방향을 채택 요구사항으로 사용한다. 아래 **[초안]**은 사용자가 위임한 작은 정책의 제안이며, 기존 합의와 구분한다. 원본 기획은 변경하지 않는다. 앱은 미구현 상태이고 고객 인터뷰·수요 조사 근거는 없다.

## 1. 범위와 객체

- **여행:** 주최자가 만들고 참여 링크를 공유하는 단위. 참가자 명단과 여러 의사결정을 가진다.
- **참가자:** 해당 여행에서 닉네임 등록을 완료한 사람. 링크 열람만으로는 등록되지 않는다.
- **의사결정:** 여행에 속하는 독립 투표 단위. 종류, 텍스트 후보, 마감 시각, 상태, 최종안을 가진다. MVP는 숙소와 출발일을 지원하며 동시에 진행할 수 있다.
- **응답:** 참가자와 의사결정 조합마다 최대 하나. 해당 의사결정의 후보 하나를 선택한다. 다른 의사결정의 응답에 영향을 주지 않는다.
- **최종안:** 주최자가 해당 의사결정의 후보 중 하나를 명시적으로 확정한 결과. 득표 현황과 별도로 표시한다.

**[초안]** 여행당 숙소·출발일 의사결정을 각각 하나씩 제공한다. 각 후보는 2–10개이며 빈 값과 동일 문구 중복을 허용하지 않는다. 출발일도 텍스트 후보를 사용한다. 생성 시 두 의사결정의 후보와 마감을 입력하고 동시에 공개한다.

계정, 결제, 예약 연동, 채팅, 알림은 제외한다. **[초안]** 공개 후 후보 편집, 의사결정 추가·삭제, 재개방, 참가자 삭제도 제외한다. 후보 변경으로 기존 응답 의미가 달라지는 문제를 피한다.

## 2. 참여와 권한

**[초안]** 생성 성공 시 참여 링크와 별도 관리 링크를 제공한다. 관리 링크 소지자가 주최자 권한을 행사하므로 복사·보관 안내를 제공한다. 참여 링크만으로 관리 권한을 얻을 수 없다.

참여 링크 소지자는 의사결정, 후보별 득표수, 참가자 명단과 각 의사결정의 응답·미응답 현황, 확정 결과를 열람한다. 투표하려면 닉네임을 등록해야 한다.

**[초안]** 닉네임은 앞뒤 공백 제거 후 1–20자, 여행 내 중복 불가다. 등록 시 브라우저에 참가자용 비밀 식별값을 저장한다. 이름만 입력해서 기존 참가자의 응답을 수정할 수 없다. 같은 브라우저로 재방문하면 기존 참가자로 복귀하며 중복 등록하지 않는다.

참가자는 자기 응답만 작성·변경할 수 있다. 주최자도 투표하려면 참가자로 등록한다. 주최자 권한으로 타인의 응답을 수정하지 못한다.

**[초안]** 다른 기기나 브라우저 저장정보 삭제 후의 참가자 복구, 관리 링크 분실 복구는 MVP에서 지원하지 않는다. 이 한계를 등록·생성 시 안내한다. 한 사람이 여러 참가자로 등록하는 것을 완전히 방지하지는 못한다.

## 3. 의사결정별 상태와 규칙

**[초안]** 상태는 `진행 중 → 마감 → 확정`이다.

| 전환 | 행위와 결과 |
|---|---|
| 생성 → 진행 중 | 주최자가 두 의사결정의 유효한 후보와 미래 마감을 제출하면 여행을 생성하고 링크를 제공한다. |
| 응답 제출·변경 | 진행 중인 의사결정에서 참가자가 후보 하나를 제출한다. 저장 성공 후 자기 선택과 집계에 반영한다. 변경은 이전 응답을 대체한다. |
| 진행 중 → 마감 | 해당 마감 시각에 응답을 잠근다. 다른 의사결정은 자체 상태를 유지한다. |
| 마감 → 확정 | 주최자가 해당 후보 하나를 선택하고 확인하면 최종안을 기록하고 모두에게 표시한다. |

**[초안]** 마감은 의사결정별로 설정하며 한국 표준시(Asia/Seoul)를 입력·표시한다. 서버 시각이 마감 이상이면 제출을 거절한다. 수동 조기 마감과 마감 연장은 제외한다.

단순 후보별 응답 수를 표시한다. **[초안]** 동률이나 응답 0건이어도 주최자가 선택할 수 있고, 최다 득표 후보를 반드시 고를 필요는 없다. 자동 확정하지 않는다. 확정 후 변경은 지원하지 않으며 확인 단계에서 이를 안내한다.

미응답자는 **현재 여행 참가자 중 해당 의사결정에 저장된 응답이 없는 사람**이다. 숙소만 응답한 사람은 출발일 미응답자에 남는다. 등록하지 않은 초대 대상은 파악할 수 없다. **[초안]** 마감 후에도 참여 등록은 허용하되 마감된 투표는 제출할 수 없다.

## 4. 실패와 복구

**[초안]**

- 저장 실패 시 성공 표시나 집계를 확정하지 않는다. 선택을 유지하고 재시도를 제공한다.
- 응답 재전송은 중복 표를 만들지 않는다. 여러 탭의 제출은 서버에서 마지막으로 수락한 값 하나를 유지한다.
- 오래 열린 화면에서 마감 후 제출하면 거절 사유와 최신 상태를 표시한다.
- 확정 요청이 겹치면 최초 성공 결과를 유지한다. 후속 요청에는 이미 확정된 결과를 표시한다.
- 잘못된 링크·권한으로 접근하면 이유를 알리고 변경을 저장하지 않는다.
- **[초안]** 실시간 동기화 대신 진입·새로고침·저장 완료 시 최신 상태를 조회한다.

## 5. 관찰 가능한 인수 시나리오

아래 검증은 모두 **계획됨 / 결과 미관찰**이다. 구현·테스트는 실행하지 않았다.

1. 링크를 열기만 하면 참가자 수가 유지되고, 닉네임 등록 후 한 명 증가한다. 같은 브라우저 재방문으로 증가하지 않는다.
2. A가 숙소만 제출하면 숙소 집계에 한 표가 생기고 출발일에는 A가 미응답으로 표시된다.
3. A가 숙소 선택을 변경하면 이전 후보는 한 표 감소하고 새 후보는 한 표 증가한다. 새로고침 후에도 유지된다.
4. 숙소만 마감되면 숙소 변경은 거절되고, 진행 중인 출발일 응답은 저장된다.
5. 참여 링크나 다른 참가자의 닉네임만으로 타인 응답 수정·최종 확정을 시도하면 거절된다.
6. 동률·0표에서 주최자가 확정하면 선택한 최종안이 다른 브라우저의 새로고침 후 보인다. 다른 의사결정은 그대로다.
7. 저장 실패 후 재시도해도 한 표만 남는다. 마감 직후 제출과 중복 확정은 위 규칙대로 처리된다.

**남은 결정:** 구현을 막는 충돌은 없다. 위 초안, 특히 복구 미지원·확정 취소 미지원은 채택 여부가 남아 있다. 수요 검증은 별도 과제이며 이 명세의 완성이 수요나 출시 준비를 입증하지 않는다.
