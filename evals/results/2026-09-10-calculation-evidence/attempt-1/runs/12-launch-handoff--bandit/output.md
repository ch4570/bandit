### 2. 첫 제공물과 출시 범위

**D1 — 제안 대상:** 직원 12명 이하 단일 점포 중, 점주 부재 시간에 교대가 있고 종이·채팅으로 인계하는 곳. 구매·승인은 점주, 작성·읽음 표시는 근무 중 직원이 맡는다. 직원 평가가 주목적인 곳은 이번 대상에서 제외한다.

**D2 — 제안 v1:** 점포당 월 29,000원, 도입비 없음. 점포별 인계 양식·접근 경로, 다음 교대의 읽음 표시, 점주 날짜별 확인, 최초 안내 40분과 월 문의 지원 30분을 제공한다. 최대 5점포다. 가온의 정해진 업무 시간에 응대하며 상시 상담·자동 알림은 약속하지 않는다.

최초 유료 제공은 **9월 28일 시작을 목표**로 한다. 첫 이용기간은 9월 28일~10월 27일이며, 준비 기간 종료인 10월 11일에는 초기 사용만 판단한다. 다음 달 재결제를 유지율로 판단하려면 후속 관찰이 필요하다.

청구는 가온이 수동 안내한다. 결제 화면은 만들지 않는다. 자동 갱신 없이 다음 기간 동의를 다시 받는다. 시작 전 취소는 전액, 시작 후 해지는 미사용 일수 비례 환불을 제안 조건으로 명시한다.

| 이번에 포함 | 보류·제외 | 재검토 조건 |
|---|---|---|
| 기록→저장→다음 교대 읽음→점주 확인, 수정·오류 복구, 기본 로그 | 자동 알림, 외부 연동, 결제 화면 | 기본 경로가 사용되고 반복 운영비가 확인될 때 |
| 모바일 웹 우선, 수동 문서 대안 | 앱 설치, 복잡한 개인 계정 | 접근 문제가 실제 장애일 때 |
| 점포 단위 상태 | 다점포·POS·근무표·급여·직원 평가, 퇴근 후 확인 강제 | 이번 실험에서는 제외 |

웹 구현이 늦으면 같은 양식·상태·가격 조건을 공유 문서로 제공한다. 점포별 접근 분리나 저장·읽음 구분이 안 되면 웹 출시를 강행하지 않는다. 대안도 충족하지 못하면 시작을 미루고 청구하지 않는다.

### 4. 마케팅과 작은 검증 실험

**바로 쓸 소개 문구**

> 다음 교대가 읽었는지, 점주도 나중에 확인하세요.  
> 마감잇은 근무 중 남긴 인계와 읽음 표시를 한곳에 모읍니다. 읽음은 업무 완료를 뜻하지 않습니다. 직원 12명 이하 단일 카페 대상, 점포당 월 29,000원·도입비 없음. 9월 28일 시작 목표로 최대 5곳에 수동 안내와 정해진 시간의 문의 지원을 제공합니다. 앱 설치나 퇴근 후 확인을 요구하지 않습니다.

**행동 유도:** “우리 매장에 맞는지 10분 설명 요청하기”

누락 감소·시간 절감은 아직 광고 문구로 사용하지 않는다.

가온은 1주차에 기존 시연 점주 3명, 이어 소개 가능한 신규 점주 최대 5명 경로를 준비한다. 소개 가능성을 확보된 고객 명단으로 계산하지 않는다. 2주차에 노출이 부족하면 지역 커뮤니티 운영진에게 초안 검토를 요청하는 계획이다. 게시 허용은 미확정이다. 직원 영상 계정은 구매자 비중이 불명확해 후순위이며, 회원·팔로워·조회 수를 합쳐 잠재 구매자로 세지 않는다.

**V1 — 제안·사용 실험:** 가온이 점포별 장부에 채널, 자격, 제안 버전·전달일, 응답, 결제·환불, 첫 가치 날짜를 기록한다.

- 응답률: 7일 응답 점포 / 제안을 실제 받은 적격 점포.
- 구매율: 7일 이내 결제 점포 / 7일 관찰을 마친 적격 제안 점포. 뒤늦은 노출은 별도 대기 집계.
- 첫 가치: 첫 인계 기회 후 48시간 내 **메모 저장→다음 교대 읽음→점주 확인**을 마친 점포 / 해당 기회가 있었던 유료 점포.
- 반복 사용: 점포별 읽음 표시 기회 / 전체 인계 기회. 메모 없는 기회, 알림 여부도 기록하고 알림 유무별 분모를 남긴다.
- 획득비: 실제 모집·소재 지출 / 결제 점포. 가온 모집 시간 환산 비용은 별도 병기하며 결제 0곳이면 산출 불가로 둔다.

**잠정 결정선:** 적격 점주 5곳 이상이 제안을 충분히 본 상태에서 2곳 이상 결제하고, 그중 2곳이 첫 가치와 최소 5회 인계 기회에서 읽음률 60% 이상을 보이면 제한 제공을 계속한다. 결제 0곳이면 추가 개발을 멈추고 거절 원인에 따라 타깃 또는 제안을 하나씩 바꾼다. 결제는 있지만 사용이 없으면 UX·중복 기록부터 수정한다. 노출·인계 기회가 부족하면 판단 유보다. 이 기준은 작은 실험의 운영 기준이며 시장 검증선이 아니다.

### 5. 소라에게 줄 UX 인계

**R1 — 시작·역할:** 점주는 가격·기간·지원·해지 조건을 보고 신청하고 가온이 점포 접근을 설정한다. 직원용 경로와 점주 관리 경로를 분리한다. 직원은 작성·읽음 표시, 점주는 기록 조회·접근 변경을 할 수 있다. 공유 접근의 표시를 개인 신원 인증이나 직원 성과로 표현하지 않는다.

**R2 — 직원 첫 화면:** `점포명 → 이번 교대 → 읽지 않은 인계 → 새 인계` 순서. 첫 방문에 “근무 중 사용”, “읽음 ≠ 처리 완료”, “고객 얼굴·연락처 입력 금지”를 짧게 보여 준다. 빈 화면은 “아직 기록된 인계가 없습니다”로 표시하며 인계 완료로 처리하지 않는다.

**R3 — 작성·저장:** 내용과 전달할 다음 교대를 입력한다. 저장 확인 뒤에만 성공을 표시한다. 실패 시 입력을 보존하고 재시도를 제공한다. 재시도로 같은 항목이 중복 생성되지 않아야 한다.

**R4 — 읽음·수정:** 다음 교대가 내용을 열고 “읽었습니다—처리 완료 아님”을 누른다. 열람만으로 읽음 처리하지 않는다. 내용 수정은 이전 버전의 읽음을 보존하고 새 버전을 ‘재확인 필요’로 표시한다.

**R5 — 점주 확인·미인계:** 날짜·교대별로 `기록 없음 / 읽음 대기 / 읽음 표시 / 재확인 필요`를 구분한다. 미확인은 다음 근무 중 확인하도록 남기며 퇴근자에게 응답을 요구하지 않는다. 접근 오류는 점주·가온을 통한 재설정, 장애는 점포별 수동 문서로 복구하고 제공 방식을 기록한다.

모바일 우선의 읽기 쉬운 글자, 명시적 버튼 이름, 키보드 접근, 색상 외 상태 문구를 요구한다. 계획된 확인 과제는 직원이 작성·재접속·읽음을 완료하고, 점주가 미확인 항목을 찾는 것이다. ‘읽음=일 완료’ 오해, 저장 실패 후 데이터 소실, 다른 점포 접근이 있으면 제공 전 수정한다. **이 검증은 아직 실행하지 않았다.**

### 6. 사업모델과 뒤집을 조건

두 대안 모두 D2의 같은 서비스를 점주에게 점포 단위로 판매한다. 도입비 대안은 최초 설정 대가를 별도로 받는다.

비용 출처는 `costs-and-delivery.md`. 원/월, 부가세 제외이며 반복 지원 인건비는 **12,500원**, 최초 온보딩은 **약 16,667원**이다.

| 계산 항목 | A: 월 29,000원 | B: 도입 30,000원 + 월 19,000원 |
|---|---:|---:|
| 월 결제 수수료 | 957 | 627 |
| 점포당 반복 기여액 | **13,543** | **3,873** |
| 첫 달 기여액: 도입 수수료·온보딩 포함 | −3,124 | 16,216 |
| 5점포 반복 손익: 고정비 포함 | **7,715** | **−40,635** |
| 5점포 첫 달 손익 | −75,618 | 21,082 |
| 반복 손익분기 점포 수 | 5곳 | 16곳 |

반복 기여액 = 월요금 × 0.967 − 2,000 − 12,500. 전체 손익은 기여액 합계에서 고정비 60,000원을 뺀다. 획득비와 장기 개발·디자인 유지비는 미포함이므로 완전한 순이익이 아니다.

**A를 잠정 추천한다.** B는 첫 달 비용을 회수하기 좋지만 반복 손익분기 16곳이 지원 한도 5곳을 넘는다. A도 5곳에서 여유가 작다. 지원이 월 60분이면 A의 5곳 반복 손익은 **−54,785원**으로 바뀐다.

지원이 30분을 넘거나 5곳 미만만 유지된다면 가격·지원 범위를 다시 정한다. 도입비 수용과 반복 지원 감소가 실제로 확인되면 B를 재검토한다. 첫 달 현금 유입만으로 B를 채택하지 않는다.

계산은 JavaScript로 실행했다. 반환값은 A/B 반복 기여액 `13,543 / 3,873`, 5곳 반복 손익 `7,715 / −40,635`, 예산 `620,000 + 180,000 = 800,000`이었다. 산술 확인이며 비용 가정의 검증은 아니다.
