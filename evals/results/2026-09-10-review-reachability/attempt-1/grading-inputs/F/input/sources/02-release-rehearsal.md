# 출시 후보 RC2 점검 기록

합성 자료 · 2026-09-09 · 예약 웹, 주문 API, 매장용 화면

공개 대상으로 검토한 버전은 RC2다. 테스트 결제 환경과 시계를 이동할 수 있는 촬영 자료 보관 환경에서 확인했다.

예약 인원 선택지는 1, 2, 3, 4명이다. 예약 생성·수정 API 모두 전체 인원에 예약자와 영유아를 포함한다. 인원을 5명으로 직접 전송하면 422와 함께 저장을 거절한다. 매장용 인원 수정도 같은 검사를 사용한다. 직원 계정으로 상한 변경 API를 호출하면 403이다. 매장 입장 화면은 예약 명단에 등록한 촬영 참여자만 체크인할 수 있다. 4명 예약에서 다섯 번째 참여자 추가는 웹과 매장 화면 모두 거절됐다.

옵션을 하나도 선택하지 않은 주문에서 다음 금액을 확인했다. 표의 총액은 결제 확인 화면, 테스트 결제 승인액, 저장된 주문 총액이 모두 같았다.

| 촬영 인원 | 촬영 기본금 | 추가 인원금 | 총액 |
| --- | ---: | ---: | ---: |
| 1명 | 60,000원 | 0원 | 60,000원 |
| 2명 | 60,000원 | 0원 | 60,000원 |
| 3명 | 60,000원 | 10,000원 | 70,000원 |
| 4명 | 60,000원 | 20,000원 | 80,000원 |

인화 배부 화면에는 체크인한 사람마다 무료 인화 한 장이 배정됐다. 4명 방문에서 네 명 모두 한 장씩 받고 잔여 무료 인화 수량은 0장이었다.

예약 마지막 화면의 파일 안내는 ‘촬영 종료 후 7일간 다운로드 가능’이다. 종료 시각부터 7일이 지나자 원본 객체가 삭제되고 기존 링크가 410을 반환했다. 8일째 매장 화면의 재전송 기능으로도 해당 파일을 가져올 수 없었다. 별도 원본 보관소는 이번 상품에 연결되어 있지 않다.

이번 점검에서 확인하지 않은 것은 실제 카드 청구, 현장 추가 인화의 결제·영수증 발행, 장애 발생 시 수동 복구 절차다.
