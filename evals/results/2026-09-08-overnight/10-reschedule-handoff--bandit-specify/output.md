Slotlet 일정 변경 개발 인계 명세

기준은 채택된 `input/booking-policy.md`와 사용자 요청이다. **새 시간이 확정되고 기존 시간이 함께 해제되기 전까지 원래 확정 예약을 유지한다.** 미승인 `input/draft.md`의 선취소, 브라우저 타이머 기준 승인, 오류 시 무조건 처음부터 다시 시작하는 흐름을 대체한다.

대상은 로그인한 예약 소유자다. 기존 로그인·예약 조회·일반 취소를 사용하며, 동일 스튜디오의 다른 60분 슬롯으로 변경한다. 성공하면 기존 선불 이용 권리를 새 예약에 승계한다. 결제·환불·반복 예약·캘린더 동기화·새 계정 시스템은 제외한다.

예약은 소유자·스튜디오·확정 시간·현재 버전을 가진다. 임시 확보는 소유자·원본 예약 버전·대상 슬롯·서버 만료 시각에 연결되며, 활성에서 사용 완료·만료·해제로 전환된다. 변경 시도는 같은 요청을 식별할 수 있어야 하며, 처리 결과를 다시 조회할 수 있어야 한다. 응답을 받지 못한 화면의 ‘결과 확인 중’은 서버에서 실패했다는 뜻이 아니다.

현재 만들 흐름은 다음과 같다.

1. 예약 상세에서 변경을 시작한다. 서버는 소유권과 기존 예약 시작까지 남은 시간을 검사한다. 조회만으로는 임시 확보하지 않는다. 대상 목록은 해당 스튜디오의 확정 예약 또는 유효한 임시 확보와 겹치지 않는 슬롯만 보여준다. 빈 목록이면 원래 예약을 유지하고 다른 날짜를 선택하게 한다.
2. 고객이 시간을 선택하면 서버가 가용성을 다시 검사하고 2분간 확보한다. 다른 고객에게는 그 시간의 용량을 제공하지 않는다. 목록 조회 이후 다른 요청이 선점했다면 선택 실패를 알리고 목록을 갱신한다. 원래 예약은 계속 확정 상태다.
3. 화면은 기존 시간·대상 시간·만료 시각을 표시하고 고객의 명시적 확정을 받는다. 사용자에게 보내는 시간은 날짜와 `Asia/Seoul` 시간대를 포함한다. 카운트다운은 안내용이며 백그라운드 복귀 시 서버 상태를 갱신한다.
4. 확정 시 서버는 소유권·변경 가능 시점·예약 버전·확보 소유권과 유효성·슬롯 용량을 재검사한다. 새 시간 확정, 기존 시간 해제, 이용 권리 승계는 전부 함께 성공하거나 전부 반영되지 않아야 한다. 부분 성공을 표시하지 않는다.
5. 성공 화면과 예약 상세는 서버의 실제 확정 시간을 보여준다. 거절·만료이면 이유와 재선택 경로를 제공한다. 통신이 끊기면 ‘결과 확인 중’으로 표시하고 동일 시도의 결과와 현재 예약을 조회한다. 재전송은 같은 시도 식별자를 사용하며 중복 예약이나 추가 변경을 만들지 않는다.

다음은 정책의 빈틈을 채우는 **추천 초안이며, 아직 채택된 정책은 아니다.**

- 소유자당 활성 임시 확보는 하나로 제한한다. 여러 탭이나 예약에서 다른 대상을 확보하려 하면 기존 확보를 안내하고 거절한다. 대상 변경은 기존 확보를 명시적으로 해제한 뒤 진행한다. 구현과 용량 점유를 단순화하는 대신 동시 비교는 제한된다.
- 서버 시각이 만료 시각보다 작을 때만 확보가 유효하다. 정확히 같으면 만료다. 청소 작업이 늦어도 만료 슬롯은 다시 확보할 수 있다.
- 기존 예약 시작까지 정확히 24시간 남으면 변경 가능하고, 그보다 적으면 불가하다. 확보와 확정 모두 검사한다. 확보 중 제한 시점을 넘으면 확정을 거절하고 확보를 해제한다.
- 다른 탭에서 예약이 변경되면 이전 버전의 새 요청은 거절하고 최신 예약을 보여준다. 이미 성공한 동일 시도의 재전송은 기존 성공 결과를 반환하며, 현재 예약도 함께 확인하게 한다.
- 일반 취소와 변경이 경쟁하면 먼저 반영된 작업만 유효하다. 취소가 먼저면 확보를 무효화하고 변경을 거절한다. 변경이 먼저면 이전 버전을 대상으로 한 취소를 거절하고 최신 예약 확인을 요구한다. 고객이 별도로 취소한 경우 원래 예약 유지 약속의 대상에서 제외한다.

수용 시나리오는 아래와 같다. **모두 계획된 검증이며 실행 결과는 없다.**

- 소유자가 유효한 확보를 확정하면 새 예약 하나와 승계된 이용 권리가 조회되고, 기존 슬롯은 다른 고객이 확보할 수 있다.
- 비소유자 또는 24시간 제한을 지난 고객의 확보·확정 요청은 거절되며 예약은 변하지 않는다. 정확한 24시간 경계도 확인한다.
- 슬롯을 둘러보기만 하면 다른 고객이 확보할 수 있다. 활성 확보가 생기면 같은 스튜디오의 겹치는 요청은 거절되지만 다른 스튜디오는 영향받지 않는다.
- 두 탭이 다른 시간을 선택하면 확보 하나만 유지된다. 한 탭에서 변경한 후 다른 탭의 오래된 확정은 예약을 다시 바꾸지 않는다.
- 브라우저에 8초가 남아 보여도 서버에서 만료되었다면 확정은 거절된다. 정확한 만료 순간 경쟁에서도 중복 확정은 발생하지 않는다.
- 확정 처리 실패 시 원래 예약과 이용 권리가 유지된다. 성공 후 응답만 유실되면 재조회·동일 요청 재전송으로 성공을 발견하며 예약이 추가되지 않는다.
- 일반 취소와 변경을 동시에 요청하면 선행 작업의 결과만 남고, 후행 작업에는 최신 상태가 안내된다.

`input/support-notes.md`는 합성 클릭 화면 워크스루 기록이다. 두 탭의 확정 버튼, 응답 유실 후 재시도 질문, 지연된 카운트다운, 만료 순간 경쟁 질문은 위 요구의 근거지만 실제 장애나 검증 통과 증거가 아니다. 기존 초안에도 구현·테스트는 없다.

개발자 1명, 목표 5일이다. 기존 취소 서비스 연동과 원자적 변경·동시성·결과 재조회 공수는 미측정이므로 완료를 확약하지 않는다. 먼저 이 의존성을 확인해 일정을 재산정한다. 일정 조정 시에도 원래 예약 보존과 결과 복구는 유지한다. 남은 제품 결정은 위 추천 규칙의 채택 여부이며, 구현 방식은 개발자가 선택한다.
