# Synthetic product notes: ParcelDesk attachment exports

ParcelDesk is an invented support-ticket product. A signed-in active workspace member
may request a ZIP of that workspace's attachments and see the status of their exports.
A member must not receive another workspace's export status, request filters, or download
location, even if they know an export ID or reuse a request key. The workspace comes from
the authenticated session, not a request-body field.

The browser supplies a request key to make retrying a timed-out submission safe. Two
submissions of the same operation within one workspace should refer to one logical export.
Different workspaces choose keys independently. The UI cannot tell whether a network timeout
occurred before or after the service accepted a request.

The pilot should recover from one queue outage or one renderer timeout without asking a
support agent to create a different logical export. We have not approved a specific retry
mechanism. Completed exports must not be regenerated by duplicate worker deliveries.

The HTTP adapter maps a raised `RuntimeError` to a 503. Queue delivery is at most once:
`take()` removes the message; failed worker calls are logged but are not requeued. A worker
process restarts with access to the same job store. A timed-out renderer may have created a
temporary object; only a job marked `complete` should expose a download location.

`implementation.py` is a reduced executable-shaped snapshot. Its in-memory dictionaries
stand in for the shared durable stores; do not infer process-local durability from that
representation. Storage, queue, renderer, and authentication adapters are outside this
review. `test_existing.py` is the current synthetic test selection, not an execution report.
