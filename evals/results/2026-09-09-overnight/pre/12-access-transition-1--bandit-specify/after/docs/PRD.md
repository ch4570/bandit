# Relayboard — 내부 요청함 PRD

이 프로젝트의 조직·사람·기록은 평가용 합성 자료다. 내부용 제품은 아직 구현·검증하지 않았다.

## 방향과 근거

D2 — 채택: [2026-08-31 전환 결정](private-intake-decision.md)에 따라 조직 내부 업무 요청함으로 전환한다. 민감한 업무를 보호하도록 기존·신규 요청을 내부로 제한한다. 공개 열람·색인 노출의 D1(2026-08-11)을 대체한다.

기존 사내 로그인·운영 콘솔을 의존성으로 사용한다. 프로젝트별 접근, 외부 고객 공유, 댓글, 첨부파일, 내보내기, 외부 서비스 동기화, 종료 요청 재개는 제외한다.

## 구성원과 권한

R1 — 사내 로그인과 소유자의 초대 명단으로 확인한 **현재 조직 구성원**만 모든 조직 요청을 읽고 작성한다. 링크·과거 파일럿 계정·다른 조직 로그인은 접근 권한이 아니다.

| 역할 | 가능한 행동 |
| --- | --- |
| 현재 구성원 | 조직 요청 열람·작성, 자기 접수 요청 편집 |
| 처리담당자 | 구성원 권한에 더해 검토 시작·담당자 지정·종료; 타인 본문 대리 편집 불가 |
| 조직 소유자 | 구성원 추가·제외, 처리담당자 지정, 정책상 조기 삭제 |
| 비로그인·미초대·제외된 사람 | 조직 요청 열람·작성·편집·처리 불가 |

소유자·처리담당자도 현재 구성원이어야 한다.

R5 — 제외된 구성원은 다음 요청부터 조회·작성·수정·처리를 거절한다. 열려 있던 화면의 저장도 반영하지 않고 권한 없음을 안내한다. 소유자에게 접근 복구를 요청하고 재추가 후 새로 조회한다. 이미 전달된 내용을 소급 회수하지는 못한다.

D3 — 추천 초안: 제외 시 처리 역할을 해제하고 재초대만으로 복원하지 않는다. 제외자의 담당 이력은 유지하고 현재 처리담당자가 재지정한다. 담당자 후보는 현재 처리담당자로 제한하여 권한 없는 사람에게 업무가 배정되지 않게 한다.

## 요청의 생애와 처리 흐름

R2 — 요청은 소속 조직, 제목, 본문, 원작성자, 접수 시각, 상태, 담당자와 종료 시각을 갖는다. 새 요청은 `접수`·담당자 미지정이다. 저장 후 상세·재조회에서 결과를 확인한다. 실패를 표시하고 권한이 유지되면 재시도한다.

원작성자만 자기 `접수` 요청을 편집한다. 검토 시작 후에는 수정 대신 상태를 안내한다. 대리 편집은 불가하다.

R3 — 처리담당자는 `접수 → 검토 중 → 종료`로 진행하고 담당자를 지정·변경한다. 종료 시 서버 시각으로 보존을 시작한다. 재개는 불가하며 담당자 변경은 원작성자에 영향이 없다.

D4 — 추천 초안: 책임을 명확히 하도록 검토 시작에 담당자 지정을 요구한다. 누락하면 선택을 안내하고 상태를 유지한다. 저장·처리는 최신 권한·상태로 판단한다. 검토 후 도착한 편집은 거절한다. 반복 종료는 시각을 유지한다. 충돌하면 최신 상태를 안내하고 재조회한다.

R4 — [데이터 정책 P1–P4](data-policy.md)가 귀속·보존·삭제의 단일 기준이다. 조직 데이터와 원작성자 기록은 탈퇴 후에도 유지한다. 종료 시각부터 정확히 180일 후 삭제하며, 미종료 요청은 만료되지 않는다. 접근 철회는 조기 삭제나 보존 재시작이 아니다. 조기 삭제는 소유자만 기존 운영 콘솔에서 수행한다. 다른 역할은 수동 검토를 요청한다. 일반 삭제 버튼·새 승인 기능은 없다. 소유자 변경·조직 이전·백업 관련 경계도 정책을 따른다.

## 이전 공개 URL과 전환

R6 — 기존 보드·개별 요청 URL에도 로그인과 현재 조직 권한을 확인한다. 비로그인은 로그인 안내, 권한 있는 로그인은 원래 목적지, 미초대·타 조직·제외자는 접근 거절로 이어진다. 비로그인 화면·공개 응답·미리보기에 제목·본문·작성자를 노출하지 않는다. 기존 요청의 귀속·작성자·상태·보존 시각을 유지하고 과거 작성자를 자동 초대하지 않는다. 공개 열람·색인 노출 경로를 닫되 외부 저장본·기존 검색 색인의 소급 회수를 보장하지 않는다.

## 성공 기준과 계획된 수용 확인

H2 — 미검증: 한 팀이 실제 업무 요청을 등록하고 담당자가 검토를 시작할 수 있다. 추천 초안은 팀·처리담당자 지정 후 14일간 실제 요청 1건 이상 저장, 그중 1건 이상 담당자 지정·검토 시작을 최소 성공으로 삼는 것이다. 요청·검토 건수는 반복 사용·도입 증거가 아니다. 요청이 없으면 기회 부재와 이용 실패를 구분한다. 모집·실행 결과는 없다.

수용 확인은 **계획됨 / 결과 미관측**이다. 실행 시 버전·환경·역할·요청을 기록한다.

| 기준 | 조건·행동 → 관찰 결과 |
| --- | --- |
| A1 대체, R1·R6 | 기존·신규 URL 비로그인 열기 → 정보 없는 로그인 안내; 구성원 로그인 → 목적지 열람; 미초대·타 조직 → 거절 |
| A2 확장, R2·R5 | 자기 접수 요청 저장·재조회 → 변경 유지; 타인·검토 중 요청 편집 → 거절; 편집 화면에서 구성원 제외 후 저장 → 반영 없음 |
| A3 유지, R3·R4 | 종료 → 서버 시각 기록; 반복 종료 → 시각 유지; 179일 유지·정확히 180일 삭제; 미종료 요청은 기간만으로 삭제 불가 |
| A4, R3·D4 | 일반 구성원 처리 → 거절; 처리담당자 지정·검토 시작 → 공유 상태 반영; 이후 도착한 편집 → 거절 |
| A5, R5·D3 | 구성원 제외 → 다음 조회·작성·처리 거절, 기록·보존 시각 유지; 재초대 → 처리 역할 자동 복원 없음 |
| A6, R4 | 작성자·처리담당자 조기 삭제 → 불가; 소유자 운영 콘솔 삭제 → 제거 |

## 역사적 증거와 미정 사항

[E1·V1·V2 원문](public-pilot.md)은 그대로 보존한다. E1: 2026-08-12~25 public-v1 공개 링크 수신자 36명 중 21명이 38건 작성했고 9명이 서로 다른 날 반복 작성했다. 방문자 수·방문 후 전환율·처리 시간·팀 도입률은 미측정이다. 내부 업무 참여자가 아니므로 공개 가설 H1과 작성률 50% 목표는 역사적 맥락이며 H2의 증거가 아니다.

V1: 2026-08-26 public-v1 스테이징 비로그인 열람 통과는 **역사적 성공**이다. 새 접근 정책은 재확인이 필요하다. V2: 같은 날 retention-worker-r3 스테이징의 가짜 시계·합성 데이터 보존 경계 통과는 변경 없는 정책에 **여전히 관련**되지만 접근 통제·운영 데이터·다른 버전을 검증하지 않는다. A2·운영 보존 작업의 실행 결과도 없다.

미정: D3·D4 추천 규칙 채택, 파일럿 팀·일정·최소 성공 기준 확정.
