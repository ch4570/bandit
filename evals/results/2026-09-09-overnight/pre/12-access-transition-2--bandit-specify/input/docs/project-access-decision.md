# 프로젝트 접근 및 외부 진행 요약 공유

평가용 합성 결정 기록. 제품 책임자가 2026-09-07 채택했다. 기존 내부 요청함의 조직 전체 열람 규칙을 이 결정으로 교체한다.

같은 회사 안에서도 인사, 영업, 제품 프로젝트의 본문을 모두 볼 수 있어서는 안 된다. 요청마다 정확히 하나의 프로젝트를 지정한다. 현재 조직 구성원이면서 그 프로젝트의 구성원인 사람만 해당 요청을 읽거나 새 요청을 만든다. 조직 소유자는 모든 프로젝트를 읽으며 프로젝트 생성·구성원 관리·요청의 프로젝트 이동을 담당한다. 프로젝트 밖 사람에게 제목·본문·작성자 정보가 목록이나 개별 URL로 노출되면 안 된다.

처리담당자는 자기가 구성원인 프로젝트 안에서만 상태와 담당자를 변경한다. 원작성자라는 사실만으로 프로젝트 접근 권한을 갖지는 않는다. 본문을 고칠 수 있는 상태와 요청 종료 이후의 처리 규칙은 기존 결정을 유지한다.

기존 요청은 모두 소유자만 접근하는 `분류 대기` 프로젝트에 넣고 소유자가 적절한 프로젝트로 옮긴다. 아직 배정하지 못했다는 이유로 조직 전체에 공개하지 않는다. 이동할 때 이전 프로젝트의 열람 권한을 그대로 이어붙이지 않는다. 원작성자나 종료 시각을 새 요청처럼 바꾸는 이관은 아니다.

외부 고객에게는 요청별 `외부 진행 카드`를 보낼 수 있다. 조직 소유자 또는 그 프로젝트의 처리담당자가 고객에게 보여줄 요약을 따로 작성하고 수신 이메일 한 개를 지정한다. 수신자는 그 이메일을 확인한 뒤 현재 공유 요약과 현재 요청 상태만 읽는다. 원문 본문, 원작성자, 내부 담당자, 다른 요청 목록은 제공하지 않는다. 고객은 본문·요약·상태를 수정하거나 조직 또는 프로젝트의 구성원이 되지 않는다. URL 전달만으로 다른 사람이 읽을 수 없어야 한다.

같은 관리 권한자가 공유를 철회하면 그 수신자의 다음 열람을 막는다. 프로젝트 이동 시 기존 공유를 어떻게 처리할지는 아직 정하지 않았다. 다른 프로젝트로 옮겨졌다고 새 프로젝트가 모르는 외부 접근을 자동 승인한 것처럼 만들고 싶지는 않다. 이 부분과 공유 요약 갱신 안내의 작은 규칙은 추천 초안으로 제안해줘.

사용자 댓글, 파일, 조직 간 이관, 여러 프로젝트에 동시에 둔 요청, 외부 고객의 요청 작성은 제외한다. 일정은 아직 확정하지 않았다. 이번 요구사항 채택만으로 프로젝트 접근이나 외부 공유 기능이 동작한다고 볼 수는 없다.
