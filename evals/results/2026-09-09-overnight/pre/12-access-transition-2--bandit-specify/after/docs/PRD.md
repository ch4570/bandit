# Relayboard — 프로젝트별 내부 요청함 PRD

평가용 합성 자료이며 채택은 구현·검증 완료가 아니다.

## 방향·권한

D5 — **채택**: [2026-09-07 결정](project-access-decision.md)으로 조직 전체 열람을 프로젝트별 접근·지정 고객 진행카드로 대체한다. [D2](private-intake-decision.md)의 처리 규칙과 [P1–P4](data-policy.md)는 유지한다. D1 공개 열람은 폐기 상태다.

R1 — 요청은 조직 내 정확히 하나의 프로젝트에 속한다. 사내 로그인·현재 조직 멤버십·프로젝트 멤버십을 충족해야 열람·작성한다. 원작성자·링크·과거 파일럿 계정은 접근권이 아니다.

| 역할 | 권한 |
| --- | --- |
| 프로젝트 구성원 | 해당 요청 열람·작성, 자기 접수 요청 편집 |
| 처리담당자 | 자신이 구성원인 프로젝트에서 상태·담당자 변경, 카드 관리; 대리 본문편집 불가 |
| 조직 소유자 | 모든 프로젝트 열람, 프로젝트 생성·구성원 관리·요청 이동·카드 관리, 조직 초대·제외·처리역할 지정, 콘솔 조기삭제 |
| 지정 외부 수신자 | 이메일 확인 후 활성 카드의 현재 요약·상태만 열람 |

소유자·처리담당자도 현재 조직 구성원이어야 한다. 소유자의 작성·편집·처리에는 일반 권한조건을 적용한다.

R5 — 조직/프로젝트 제외·이동 후 다음 조회·저장·처리·카드 관리에 최신 권한을 적용한다. 열린 화면도 무권한 저장을 거절한다. 소유자에게 복구 요청 후 재조회한다.

D3 — **추천 유지·보완**: 조직 제외 시 처리역할을 해제하고 재초대만으로 복원하지 않는다. 담당자 후보는 해당 프로젝트의 현재 처리담당자다. 제외·이동으로 부적격인 담당자는 미지정으로 바꾸고 이력은 유지한다. 책임 공백은 현재 처리담당자가 재지정한다.

## 처리·이동·데이터

R2 — 요청은 제목·본문·원작성자·접수 시각·상태·담당자·종료 시각을 가진다. 프로젝트 선택·저장하면 접수/담당자 미지정이다. 재조회로 저장을 확인하고 실패는 안내·재시도한다. 접근권 있는 원작성자만 자기 접수 요청을 편집한다.

R3 — 처리담당자가 `접수 → 검토 중 → 종료`로 진행한다. 검토 이후 편집·종료 후 재개는 불가하다. 담당자 변경은 원작성자를 바꾸지 않는다. D4 — **추천 유지**: 유효한 담당자 없이는 검토를 시작하지 않는다. 최신 권한·상태로 판단하며 늦은 편집은 거절하고 충돌은 재조회한다. 서버 종료시각은 반복 종료에도 유지한다.

R7 — 기존 요청은 소유자만 접근하는 `분류 대기`에 넣고 소유자가 같은 조직의 목적 프로젝트로 이동한다. 과거 작성자 자동초대·미분류 전체공개는 없다. 이동 후 목적 프로젝트 권한만 적용한다. 원작성자·본문·상태·접수/종료 시각·보존 기한은 유지한다. **추천**: 이동·권한 변경·공유 철회를 함께 적용하여 중간 노출을 막는다. 실패하면 기존 소속 유지·재조회·재시도한다. 경합은 완료시점의 소속·권한·상태로 판단한다.

R4 — [데이터 정책 P1–P4](data-policy.md)가 귀속·보존·삭제의 단일 기준이다. 탈퇴 후에도 조직 데이터·원작성자·처리 기록을 유지한다. 종료부터 정확히 180일 후 삭제하고 미종료 요청은 만료되지 않는다. 제외·이동·공유 철회는 조기삭제나 보존 재시작이 아니다. 조기삭제는 소유자만 기존 운영 콘솔에서 수행한다. 다른 역할은 수동검토를 요청한다. 삭제 버튼·승인 기능은 없다. 소유자 변경·조직 이전·백업 경계도 P1–P4를 따른다.

## 외부 공유·철회·이전 URL

R8 — 소유자 또는 해당 프로젝트 처리담당자가 별도 요약과 수신 이메일 하나를 지정한다. 지정 이메일 확인 전에는 숨기고 실패하면 재확인을 안내한다. 수신자는 현재 공유 요약·현재 요청 상태만 읽는다. 원문·원작성자·내부 담당자·다른 요청 목록은 제공하지 않는다. 수정권·멤버십은 없고 URL 전달만으로 열람하지 못한다.

D6 — **추천 초안**: 요청당 활성 카드 하나로 시작한다. 별도 저장한 요약만 공개한다. 갱신 후 재열람에는 최신 요약·갱신시각·변경 안내를 표시한다. 안내 범위를 제한하도록 이메일 알림은 제외한다. 실패하면 기존 요약을 유지한다. 수신자 교체는 기존 공유 철회·새 이메일 확인을 요구한다.

R9 — 현재 관리 권한자가 철회하면 다음 열람부터 차단한다. D7 — **추천 초안**: 이동 시 기존 카드를 자동 철회한다. 미승인 접근 승계를 막도록 새 프로젝트 관리자가 요약·수신자를 검토해 재공유하고 수신자는 재확인한다. 이전 URL은 복원하지 않는다. 요청 삭제도 카드를 차단한다. 읽은 사본은 회수하지 못한다.

R6 — 기존 보드·개별 URL도 권한검사한다. 비로그인은 로그인 안내, 권한자는 목적지, 무권한자는 거절이다. 목록·개별 URL·공개 응답·미리보기에서 무권한자에게 제목·본문·작성자를 숨긴다. 카드는 별도 제한 경로다. 공개 색인은 닫되 과거 색인·저장본 회수는 보장하지 않는다.

기존 사내 로그인·운영 콘솔에 의존한다. 댓글·파일·내보내기·외부 동기화·조직 간 이관·다중 프로젝트 소속·외부 고객 작성은 제외한다.

## 증거·남은 결정

[E1·V1·V2](public-pilot.md): E1(public-v1, 2026-08-12~25)은 공개 링크 수신자 36명 중 21명·38건 작성, 9명 반복 작성이다. 방문자·방문전환율·처리시간·팀도입률은 미측정이다. 공개 H1·50% 목표는 역사적 맥락이며 내부 수요·접근·공유를 입증하지 않는다.

V1(2026-08-26, public-v1 스테이징) 비로그인 열람 통과는 **역사적 성공**, 현재 접근은 **재확인 필요**다. V2(동일 날짜, retention-worker-r3 스테이징)의 가짜 시계·합성 요청 2건 179/180일 통과는 보존정책에 **여전히 관련**되나 운영 데이터·다른 버전·접근통제는 미검증이다.

[V3](private-prototype-checks.md)(2026-09-04, internal-preview-2 스테이징)의 조직 계정 4개(인사 무관 2개 포함) 열람 통과는 **역사적 성공**이다. 타 조직 3개·제외 계정 1개의 새 열람 거절은 **여전히 관련**되나 새 버전에서 재확인한다. 열린 편집 저장·프로젝트 접근은 미실행, 카드는 미구현이다. 조직 ID만 비교하자는 개발 제안은 미채택이다. 보존 작업은 변경·재실행하지 않았다.

H2 내부 업무 가능성은 미검증이다. **추천**: 지정 팀·프로젝트에서 14일간 실제 요청 1건 저장·1건 담당자 지정/검토 시작을 관찰한다. 반복사용·도입 증거는 아니며 무요청은 기회 부재/이용 실패를 구분한다. 실고객 파일럿·속도·사용률·비교 성과는 없다.

미정: D3·D4·D6·D7·이동 경합 초안 채택, 이메일 확인 방식, 파일럿 팀·일정·성공기준. 제품 코드·테스트는 실행하지 않았다.
