# Relayboard — 내부 요청함 PRD

합성 자료 기반 계획이며 채택은 구현·배포·검증 완료를 뜻하지 않는다.

## 방향과 범위

D3 — **채택**, 제품 책임자, 2026-09-07, [프로젝트 접근 결정](project-access-decision.md). 민감한 프로젝트 정보를 보호하도록 D2의 조직 전체 열람을 프로젝트별 접근으로 대체하고 지정 고객용 외부 진행 카드를 포함한다. [D2](private-intake-decision.md)(2026-08-31)의 나머지 처리·내부 전환 정책과 [P1–P4](data-policy.md)는 유지한다. D1 공개 열람은 대체된 과거 정책이다.

목표는 실제 요청의 등록→담당자 지정→검토 시작과 고객 진행 확인이다. 사내 로그인·운영 콘솔에 의존한다. 댓글·파일·내보내기·외부 동기화·조직 간 이관·다중 프로젝트 소속·고객 작성·종료 후 재개는 제외한다.

## 현재 권한

R1 — 요청은 한 조직과 정확히 하나의 프로젝트에 속한다. 내부 사용자는 사내 로그인 후 현재 조직 초대 명단과 해당 프로젝트 명단에 모두 있어야 열람·등록한다. 원작성자·파일럿 계정·링크 소지만으로 권한을 얻지 않는다.

| 역할 | 권한 |
| --- | --- |
| 프로젝트 구성원 | 해당 요청 열람·등록, 자기 접수 본문 수정 |
| 처리담당자 | 구성원인 프로젝트에서 상태·담당자 변경, 카드 관리; 타인 본문 수정 불가 |
| 조직 소유자 | 모든 프로젝트 열람, 프로젝트 생성·구성원 관리·요청 이동, 조직 구성원·처리담당자 관리, 카드 관리·콘솔 삭제 |
| 외부 수신자 | 이메일 확인 후 활성 카드의 현재 요약·상태만 열람 |

**유지 추천:** 권한 확대를 막도록 소유자·처리담당자도 현재 조직 구성원이어야 한다. 소유자의 작성에는 프로젝트 자격, 처리에는 처리담당자 지정이 필요하다.

R5·R6 — 조직/프로젝트 제외는 다음 열람·저장·처리부터 적용하며 열린 화면도 현재 권한을 재확인한다. 목록·검색·URL·데이터 응답·미리보기에서 무권한자에게 제목·본문·작성자를 숨긴다. 이전 공개 URL도 비로그인은 로그인, 권한자는 목적지, 무권한자는 접근 불가·소유자 문의를 안내한다. 검색엔진 공개는 금지하며 전달·색인된 사본은 회수하지 못한다. **유지 추천:** 이력과 책임을 구분하도록 자격 없는 담당자는 활동 불가로 표시하고 현재 프로젝트 처리담당자가 재지정한다.

## 처리·이동·데이터

R2·R3 — 제목·본문·원작성자·접수 시각·상태·담당자·종료 시각을 보관한다. 등록은 `접수`, 담당자 미지정, 종료 시각 없음이다. 성공은 재열기로 확인하고 실패는 성공 표시 없이 입력 유지·재시도한다. 현재 접근 가능한 원작성자만 접수 본문을 수정한다. 저장 시 권한·상태를 재확인한다. 권한 상실·검토 중·종료 수정은 거절·안내한다.

처리담당자가 `접수 → 검토 중 → 종료`로 처리한다. **유지 추천:** 책임 명확화를 위해 검토 시작에 프로젝트 처리담당자를 지정하며 재지정 가능하다. 단계 생략·재개는 불가하다. 종료는 서버 시각, 경쟁 변경은 최신 상태 안내·재확인, 중복 종료는 시각 불변이다. 접근권자에게 변경을 반영한다.

R7 — 기존 요청은 소유자만 접근하는 `분류 대기`에 넣고 소유자가 분류한다. 소유자만 같은 조직의 프로젝트로 이동한다. 이전 권한은 승계하지 않으며 원작성자도 대상 자격이 필요하다. 조직 귀속·본문·원작성자·상태·이력·종료 시각·보존 기한은 유지한다. **추천:** 노출 방지를 위해 이동·권한 변경·공유 철회를 함께 확정한다. 실패는 기존 상태 유지·재시도다. 담당자 자격도 재평가한다.

R4 — P1–P4가 귀속·보존·삭제의 기준이다. 종료부터 정확히 180일 후 삭제하며 미종료 요청은 만료하지 않는다. 탈퇴·철회·이동·담당자 변경은 삭제나 보존 시계 재시작 사유가 아니다. 소유자만 기존 콘솔에서 조기 삭제한다. 작성자·처리담당자는 수동 검토를 요청한다. 일반 삭제·새 승인 기능은 없다. 소유자 교체에도 귀속은 유지한다.

## 외부 공유와 철회

R8 — 소유자 또는 현재 프로젝트 처리담당자가 별도 요약과 수신 이메일 한 개를 지정한다. 이메일 확인 후 현재 요약·현재 요청 상태만 제공한다. 원문·원작성자·내부 담당자·다른 요청 목록은 숨긴다. 고객 수정·구성원 자격·전달 URL만의 접근은 불가하다. 현재 관리 권한자의 철회는 다음 열람부터 차단한다.

**추천:** 관리 단순화를 위해 요청당 활성 카드 하나로 한다. 수신자 변경은 철회·새 이메일 확인을 요구한다. 이동은 기존 공유 철회 후 대상 관리자가 요약·수신자를 재확인해 재공유한다. 이전 링크는 차단한다. 새 프로젝트의 묵시적 승인을 막기 위함이다.

**추천:** 요약 미리보기 후 저장하며 다음 열람에 현재 요약·갱신 시각·변경 안내를 표시한다. 추가 유통을 줄이도록 이메일 알림은 제외한다. 실패는 기존 요약 유지·재시도다. 열린 카드도 다음 요청에서 수신자·공유 상태를 재확인한다. 철회·삭제는 내용 없이 이용 불가다. 공유는 보존을 연장하지 않으며 삭제 후 카드도 차단한다. 전달된 내용은 회수하지 못한다.

## 근거와 성공 기준

[E1·V1·V2](public-pilot.md)는 합성 기록이다. E1: 2026-08-12~25 public-v1 공개 커뮤니티 수신자 36명 중 21명이 38건 작성, 9명 반복 작성. 방문자·방문 전환율·내부 도입률·처리 시간은 불명이다. H1 작성자 50% 목표는 현재 기준에서 제외한다. V1: 08-26 public-v1 스테이징 비로그인 열람 통과는 역사적 결과이며 현재 접근은 재검증한다.

V2: 08-26 retention-worker-r3 스테이징 가짜 시계·합성 종료 2건의 179일 유지/180일 삭제 통과는 변경 없는 보존 규칙과 당시 조건에 유효하다. 운영·접근·다른 버전 검증은 아니다.

[V3](private-prototype-checks.md): 09-04 internal-preview-2 스테이징 조직 계정 4개(인사 무관 2개 포함)의 열람 통과는 당시 D2의 역사적 성공이다. 타 조직 3개 거절·제외 계정 1개 새 페이지 거절은 해당 조건에서 유효하나 프로젝트 격리는 재검증한다. 열린 편집 저장·프로젝트 접근은 미실행, 외부 카드는 부재했다. 조직 ID만 비교하자는 메모는 미채택이며 D3을 충족하지 않는다. 보존 작업은 변경·재실행되지 않았다.

H2 내부 효용은 미확인이다. **유지 추천:** 설정 후 14일간 초대 인원·작성자·요청·검토 시작 건수를 기록한다. 실제 요청 1건의 등록→담당자 지정→검토 시작이 목표다. 효율·도입률 증거는 아니며 미실행·기록 누락·완료 없음을 구분한다. 모집·실고객 실행 결과는 없다.

## 예정 수용 시나리오

미실행 계획이며 통과 증거가 아니다.

- A1(R1·R6): 비로그인·미초대·타 조직·프로젝트 밖 계정의 목록/이전 URL/직접 요청은 정보 비노출. 이중 구성원은 해당 프로젝트, 소유자는 전체 열람.
- A2(R2·R3): 자기 접수 저장·재열기 성공, 타인·검토 중·종료 수정 거절. 편집 도중 검토 시작도 저장 거절. 실패는 입력 복구·재시도, 일반 구성원 처리는 거절.
- A3(R3·R4): 검토→종료 반영, 중복 종료 시각 불변. 179일 유지·정확히 180일 삭제·미종료 유지.
- A5(R5): 조직/프로젝트 제외 후 열린 화면의 저장·처리·재열람 거절. 남은 접근권자에게 원작성자·이력 유지, 기한 불변.
- A6(R4·R8): 일반 삭제 거절, 콘솔 삭제 후 내부 요청·카드 이용 불가. 소유자 교체에도 귀속 유지.
- A7(R7): 분류 대기는 소유자만 열람. 이동 후 이전 구성원·원작성자는 대상 자격 없으면 차단, 대상 구성원은 열람. 이력·종료 시각·기한 불변; 실패는 기존 상태 유지.
- A8(R8): 지정 이메일 확인 후 요약·상태만 표시. 전달 링크·다른 이메일·고객 수정은 거절. 갱신 재열람에 새 요약·안내, 실패는 이전 요약 유지.
- A9(R7·R8): 철회·수신자 변경·이동 후 열린 카드의 다음 열람 차단. 대상 관리자의 재공유·이메일 확인 후 새 카드만 접근하고 이전 링크는 차단 유지.

남은 결정: 추천 초안 채택, 파일럿 팀·일정·기록 담당자, 외부 이메일 확인 수단. 백업 파기·법정 보존 의무는 원정책에서도 미확정이다.
