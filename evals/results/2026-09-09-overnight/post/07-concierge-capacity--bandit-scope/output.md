**추천안은 기존 회원 5명으로 제한한 수동 예약 파일럿입니다.** 기존 폼·비공개 시트·이메일을 재사용하고, 신규 화면 개발은 보류하세요. 가장 강한 대안은 예약 충돌 방지 기능 개발이지만, 첫 출시에서는 운영량을 제한하는 편이 대여 완료까지 지킬 가능성이 높습니다. 수동 확인이 반복해서 누락되거나 운영량을 늘려야 할 때 자동화를 재검토합니다.

**받을 이용자와 운영 한도**

- 참여 희망 36명 중 평일 17–18시의 지정 수령·반납 시간에 동의하는 기존 회원 5명만 초대합니다. 기존 신원·대여 자격 확인을 유지합니다.
- 대여 가능 재고는 드릴 3개와 샌더 2개입니다. 수리 대기 드릴은 계속 제외합니다.
- 하루 **요청 심사 2건, 수령 2건, 반납·검사 2건**까지만 배정합니다. 요청은 초대일을 나눠 받고, 정원을 넘으면 폼을 닫습니다. 같은 날 발생하는 업무를 합산해 관리합니다.

자료의 가상 리허설 추정으로 이 한도는 `2×6 + 2×5 + 2×7 = 36분/일`입니다. 남은 24분은 지연·파손 대응과 도착 지연에 남깁니다. 예외 2건이면 20분이 추가되므로 여유가 크지는 않습니다. 실제 지속 가능한 처리량으로 검증된 수치는 아닙니다. 전원 수용 시 예상 피크는 `8×6 + 5×5 + 5×7 = 108분`으로, 예외 없이도 매니저의 60분을 넘습니다.

**구현·설정할 것과 수동 처리할 것**

신규 제품 코드는 만들지 않습니다. 폼 안내에 “접수는 예약 확정이 아님”, 처리 시간, 참여 제한을 명시하고, 시트에 일별 업무 한도와 수령·반납 약속 시간을 함께 기록하도록 정리합니다. 확정·불가·변경 이메일 양식도 준비합니다.

매니저가 다음 과정을 한 시간 안에서 처리합니다.

1. 요청을 검토하며 회원 자격, 진행 중 대여·중복 요청, 개별 공구 상태, 예약 충돌, 수령일과 반납일의 업무 한도를 확인합니다.
2. 조건을 만족하면 공구 식별번호와 수령·반납 시간을 시트에 먼저 기록하고 확정 이메일을 보냅니다. 발송 여부도 남깁니다.
3. 수령 시 신원을 확인하고 대여 상태를 기록합니다. 반납 시 검사까지 끝내야 다시 대여 가능으로 바꿉니다. 파손품은 격리합니다.
4. 연체·파손 시 상태를 갱신하고 영향을 받는 회원에게 변경 사실과 가능한 대안을 알립니다. 연락 미완료도 남겨 재확인합니다.

첫 주에는 **현재 대여 중인 공구의 다음 예약을 미리 확정하지 않습니다.** 반납·검사 후에만 다시 확정해 연체가 다음 약속으로 번지는 위험을 줄입니다. 수령·반납은 서로 겹치지 않는 약속 시간으로 배정합니다. 예외로 시간이 부족해지면 신규 요청 처리를 미루고 기존 대여의 수령·반납·연락을 우선합니다.

**버리는 것과 출시 전 확인**

회원 상태 페이지, 새 운영 화면, 자동 알림, 대시보드는 미룹니다. 결제·보증금·배송·공개 가입은 기존 제외 결정을 유지합니다. 대신 이용자는 이메일로 상태를 확인하고, 재대여까지 기다려야 합니다.

개발자 5일은 기존 도구 설정과 운영 절차 정리, 매니저와의 검증 1일, 발견한 문제 수정·재확인에 배분합니다. 검증도 매니저의 17–18시 가용 시간 안에서 해야 합니다.

출시 전에는 충돌 요청, 중복 대여, 미발송 확정 메일, 연체, 파손, 반납 후 재배정을 연습하고, **일일 혼합 업무가 60분 안에 끝나는지**, 회원이 지정 시간과 접수·확정 구분을 이해하는지 확인하세요. 아직 검증은 실행되지 않았습니다. 시간이 넘으면 요청 심사를 하루 1건으로 줄이고 초대를 늦춥니다. 이미 확정한 수령·반납을 처리할 여력이 확보되지 않으면 추가 확정을 중단합니다.
