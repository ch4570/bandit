**GatherTrip — 개발 전달용 MVP 명세**

근거: `input/request.md`, `input/brief.md`. 기존 방향을 구체화한 명세이며 원본은 수정하지 않는다. 아래 **채택**은 사용자·창업자가 정한 방향, **초안**은 누락된 정책에 대한 제안이다.

**목표와 범위**

4~8명 여행 모임이 로그인 없이 참여하고, 같은 여행의 숙소와 출발일을 각각 투표한 뒤 주최자의 최종 선택을 확인한다. 개발자 1명, 2주 MVP로 여행 생성 → 링크 공유 → 참여 → 투표·수정 → 개별 마감 → 최종 확정까지 제공한다.

계정, 결제, 예약 연동, 채팅, 알림은 제외한다. **초안:** 자동 마감, 참가자 삭제, 재개표, 확정 취소, 기기 간 신원 복구도 제외한다.

**객체와 권한**

| 객체 | 의미와 규칙 |
|---|---|
| 여행 | 제목, 주최자 권한, 공유 링크, 참가자 목록, 복수의 결정을 가진다. |
| 참가자 | 여행에 닉네임을 등록한 사람. 링크 열람만으로는 생성되지 않는다. |
| 결정 | 숙소 또는 출발일 중 하나. 자체 후보·상태·응답·최종안을 가진다. 다른 결정의 상태에 영향을 주지 않는다. |
| 후보 | 주최자가 입력한 텍스트 선택지. 해당 결정에 속한다. |
| 응답 | 참가자와 결정의 조합당 최대 1개. 그 결정의 후보 하나를 가리킨다. |
| 최종안 | 주최자가 마감된 결정에서 명시적으로 선택한 후보. 투표 집계와 별도로 기록한다. |

**채택:** 참가자는 자기 응답만 변경하고, 주최자가 최종안을 확정한다.  
**초안:** 공유 링크 소지자는 참가 전에도 후보, 닉네임 목록, 집계, 최종안을 읽을 수 있다. 응답 제출에는 참가 등록이 필요하다. 다른 사람의 개별 선택은 표시하지 않고 후보별 표수와 응답 여부만 공개한다.

**진입과 신원 — 초안**

- 주최자는 여행 제목과 닉네임을 입력해 여행을 생성하며 참가자로도 등록된다.
- 일반 참가자는 공유 링크에서 닉네임을 제출해야 목록에 추가된다. 앞뒤 공백 제거 후 빈 이름과 동일 여행의 중복 이름은 거절한다.
- 서버가 발급한 여행별 참가자 식별 토큰을 브라우저에 보관한다. 같은 브라우저로 다시 방문하면 기존 참가자로 인식한다. 닉네임만으로 기존 참가자의 권한을 얻을 수 없다.
- 주최자 관리 권한은 일반 공유 링크와 분리한다. 생성 시 별도 관리 링크와 보관 안내를 제공한다. 관리 링크 소지자가 주최자 권한을 가지며 일반 공유 화면에는 노출하지 않는다.
- 다른 기기나 브라우저 데이터 삭제 후 참가자 자동 복구는 지원하지 않는다. 새 등록은 별도 참가자로 집계되므로 중복 신원이 생길 수 있다. 관리 링크와 저장된 권한을 모두 잃으면 주최자 복구도 지원하지 않는다.

**핵심 흐름과 상태**

1. **결정 준비:** 주최자가 숙소·출발일 후보를 입력한다. **초안:** 여행당 유형별 결정 1개씩, 각각 후보 2~5개로 제한한다. 초기 상태는 `준비 중`이며 주최자만 볼 수 있다. 후보는 공백만 있거나 동일 문구가 중복될 수 없다. 출발일도 시간 계산 없는 텍스트이며 연도를 포함하도록 안내한다.
2. **투표 시작:** **초안:** 주최자가 각 결정을 따로 공개하면 `투표 중`이 된다. 공개 이후 후보 추가·수정·삭제는 막아 이미 제출한 응답의 의미를 보존한다. 숙소와 출발일은 동시에 열릴 수 있다.
3. **응답:** 참가자는 열린 결정에서 후보 하나를 선택하고 제출한다. 저장 성공 후 자기 선택, 표수, 응답 여부가 갱신된다. 마감 전 변경 제출은 기존 응답을 대체하며 표를 추가하지 않는다. **초안:** 응답 철회 기능은 제외한다.
4. **마감:** **초안:** 주최자가 해당 결정의 ‘투표 마감’을 누르면 `마감·확정 대기`로 바뀐다. 자동 마감은 없다. 응답 추가·변경을 중단하고 마감 당시 참가자와 집계를 보존한다. 다른 열린 결정은 계속 응답할 수 있다.
5. **확정:** 주최자가 마감된 결정의 후보 하나를 선택해 확인하면 `확정` 상태가 된다. 그룹 화면에 ‘주최자 확정’으로 표시한다. **초안:** 최다 득표와 무관하게 선택할 수 있으며 동률·응답 0명도 확정을 막지 않는다. 확정 후 수정과 재개는 지원하지 않는다.

**미응답과 동시 처리 — 초안**

각 결정에 `응답 n명 / 대상 m명`과 미응답 닉네임을 표시한다. 숙소만 응답한 사람은 출발일에서 미응답이다. 투표 중에는 현재 등록된 참가자가 대상이며 신규 참여자도 포함한다. 마감 후 합류한 사람은 그 결정의 대상·미응답 집계에서 제외한다.

마감과 응답이 경합하면 서버가 먼저 반영한 작업을 기준으로 처리한다. 마감 이후 도착한 제출은 거절하고 최종 저장된 선택과 마감 상태를 보여준다. 같은 참가자의 반복 제출은 응답 하나만 남긴다. 중복 확정 요청도 최종안 하나만 유지하며 후속 요청은 기존 확정 결과를 반환한다.

저장 실패·연결 끊김 때 성공으로 표시하지 않는다. 입력한 선택을 유지하고 재시도와 상태 새로고침을 제공한다. 저장 여부가 불명확하면 서버 상태를 다시 확인한다. 다른 방문자는 화면 진입·새로고침으로 최신 집계와 결과를 확인할 수 있다. 실시간 동기화는 제외한다.

**수용 시나리오 — 모두 계획된 검증**

| 조건·행동 | 관찰 가능한 결과 |
|---|---|
| 공유 링크만 연다 | 참가자 수가 늘지 않는다. 닉네임 등록 성공 후에만 목록에 나타난다. |
| 숙소와 출발일을 동시에 연다 | 각 후보·응답·표수가 분리된다. |
| 숙소에만 응답한다 | 숙소 미응답 목록에서는 빠지고 출발일 목록에는 남는다. |
| 마감 전 선택을 A에서 B로 변경한다 | A는 1표 감소, B는 1표 증가하며 총 응답자는 그대로다. 새로고침 후에도 B가 유지된다. |
| 참가자가 다른 사람의 응답 또는 관리 작업을 요청한다 | 거절되며 공유 상태가 변하지 않는다. |
| 숙소를 마감한 뒤 두 결정에 응답한다 | 숙소 제출은 거절되고 열린 출발일 제출은 반영된다. |
| 마감 뒤 신규 참가자가 가입한다 | 마감된 결정의 분모는 유지되고 열린 결정의 미응답자에 추가된다. |
| 동률 또는 무응답 상태에서 주최자가 확정한다 | 선택한 후보가 최종안으로 표시되고 이후 변경은 거절된다. |
| 저장 응답이 유실되어 재시도한다 | 서버 확인 후 응답 하나와 실제 집계를 표시한다. |

**개발 인계와 남은 판단**

기존 방향에 결정별 상태·응답 소유권·미응답 분모·마감 경합·최종안 불변 규칙을 추가했다. 1주차는 생성·권한·참여·결정 공개·투표, 2주차는 마감·확정·실패 복구와 위 시나리오 검증에 배정하는 초안이다.

복구 없는 브라우저 신원, 공개 후 후보 고정, 수동 마감은 재검토 시 구현 범위가 달라지는 주요 초안 정책이다. 현재 명세에는 일관된 기본값을 두었으며 미정으로 남긴 구현 차단 항목은 없다.

팀은 아직 앱을 구현하지 않았고 고객 인터뷰·수요 연구도 없다. 수요와 2주 내 완료 가능성은 검증되지 않았다. 구현·테스트 실행은 하지 않았으며, 위 기준은 통과 증거가 아니다.
