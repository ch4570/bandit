# 마감잇: 9월 14일~10월 11일 유료 실험 실행안

**잠정 추천은 ‘점주가 교대 인계 여부를 확인하는 서비스’다.** 직원은 근무 중 한 번 기록하고, 다음 교대는 읽었다고 표시하며, 점주는 날짜별로 미확인 인계를 찾는다. 단순 메모장과의 차이는 이 연결에 둔다. 업무 완료 보증이나 직원 감시는 제공하지 않는다.

이번 4주는 최대 5점포에 **14일·점포당 14,500원**으로 제공하고 종료한다. 월 29,000원은 이후 검증할 정규 요금 후보이며, 자동 갱신하지 않는다. 아래 선택과 기준은 모두 제안이다. 실제 연락·게시·결제·개발·검증은 실행하지 않았다.

## 1. 리서치 판단과 먼저 확인할 것

근거는 모두 제공된 **합성 자료**다. 실제 시장 수요나 성과로 일반화할 수 없다.

| [연구 기록](input/research-records.md), I-01·02 | A 점주는 부재중 읽음 확인을 원하고, 직원은 중복 작성·퇴근 후 응답을 싫어한다 | **D1:** 근무 중 단일 기록→다음 교대 읽음→점주 확인 |
| I-04 및 9/9 관찰 | 읽음과 처리 완료가 혼동된다 | **D2:** ‘읽었어요’만 사용하고 처리 완료 기능은 보류 |
| I-03·05, 무료 사용 종료 반응 | B는 무료 채팅으로 복귀, C는 확인 화면을 조건으로 관심 표시 | 무료 대안 대비 추가 가치와 구매를 별도로 검증 |
| 8/26~9/8 수동 사용 | 3점포·42회 인계 기회 중 메모 28회, 읽음 20회 | 인계 기회 대비 읽음은 47.6%; 자발적 반복 사용은 미확인 |

인터뷰는 지인·소개로 모집한 4점포의 6명이다. 같은 점포의 점주와 직원은 독립 점포 표본이 아니다. 무료 공유 문서 사용에는 가온의 설명과 직접 알림이 개입했다. 알림 여부와 사용의 교차 집계, 도입 전 비교값이 없으므로 **누락 감소·시간 절감·알림 효과를 주장하지 않는다.** 유료 고객은 0곳이다.

9/14~16 가온이 다음 질문을 확인하고 제안을 조정한다.

- **점주:** 최근 재확인이 필요했던 인계는 무엇이었고, 채팅으로 해결되지 않은 이유는 무엇인가? → 구체적 사례가 없으면 첫 타깃에서 제외.
- **직원:** 출근 중 접속 가능한 기기·경로가 있는가? 읽음이 업무 완료와 다르다는 설명을 이해하는가? → 개인 기기 강제가 필요하면 참여시키지 않는다.
- **구매자:** 아래 날짜·가격·수동 제공 가능성을 보고 실제 결제할 의사가 있는가? → 말로 한 관심과 입금을 분리 기록.
- **운영:** 외부 알림 없이 다음 교대가 열 수 있는가? → 사용 기록에 알림 개입을 붙여 확인한다.

## 5. 소라에게 넘길 UX 요구와 인수조건

**R1—입장·역할.** 점주는 O1 조건 확인→결제 확인→접근 경로 설정→샘플 인계를 따라간다. 직원은 매장 QR/링크로 접속하고 ‘현재 근무 교대’를 선택한다. 점주 관리 접근은 직원 공유 접근과 분리한다. 공유 접근은 개인 신원 증명이 아니므로 **“누가 읽었는지”가 아니라 “어느 교대가 읽음 표시했는지”** 보여준다.

**R2—직원 홈.** 점포·현재 교대→미확인 인계→전체 기록→‘인계 남기기’ 순서다. 첫 사용에는 짧은 예시와 “읽음 ≠ 처리 완료”를 표시한다. 빈 화면은 ‘등록된 인계 없음’으로 보여주며 완료 상태로 해석하지 않는다.

**R3—작성·읽음.** 작성 화면은 인계 내용, 다음 교대, 저장 버튼을 제공한다. 저장 확인 후에만 성공을 표시하고 실패 시 입력을 유지해 재시도한다. 다음 교대는 내용을 열고 명시적으로 ‘읽었어요’를 누른다. 열람만으로 읽음 처리하지 않는다. 반복 누름은 중복 집계하지 않는다.

**R4—수정·미인계 복구.** 작성 교대가 내용을 수정하면 수정 시각과 이전 내용을 남기고 새 내용은 재확인을 요구한다. 이전 읽음 기록은 당시 내용에 연결한다. 다음 교대가 확인하지 않으면 ‘미확인’으로 남기고 현재 근무자가 대면 전달 후 실제 읽음 표시를 요청한다. 점주가 대신 읽음 처리하거나 퇴근자에게 응답을 강제하지 않는다.

**R5—점주 화면·종료.** 날짜→교대→인계 내용→읽음/미확인 순으로 조회한다. 직원 순위는 없다. 접근 실패는 재접속·가온 문의를 안내하고, 링크 유출 시 교체한다. 종료 시 기록 사본과 서비스 종료 안내를 제공한다.

모바일 우선, 읽기 쉬운 글자·명시적 버튼 이름·키보드 접근·색상 외 상태 문구를 적용한다.

9/21~23 소라가 직원 역할 2명·점주 역할 1명에게 작성→읽음→수정→미확인 찾기를 수행하도록 한다. 핵심 기준은 **설명 없이 읽음/완료 차이를 말하고, 다른 기기에서 저장·읽음·수정 상태를 확인하는 것**이다. 접근 분리·저장 실패 복구도 도윤이 확인한다. 이는 예정된 검증이며 통과 기록은 없다.
