# 마감잇: 9월 14일~10월 11일 유료 실험 실행안

**잠정 추천은 ‘점주가 다음 교대의 읽음 여부를 확인하는 인수인계 서비스’입니다.** 직원에게는 한 번 기록하고 출근해서 확인하는 흐름을, 점주에게는 미확인 인계를 찾아보는 화면을 제공합니다. 메모 작성량보다 **운영자 독촉 없이 인계가 이어지고 점주가 비용을 지불하는지**를 확인합니다.

아래는 BANDIT에 따른 계획·인계 문서입니다. 모든 입력은 합성 자료이며, 제안된 연락·게시·결제·검증은 실행하지 않았습니다.

**D1 — 첫 타깃:** 직원 12명 이하 단일 카페 중 점주가 일부 교대에 부재하고, 다음 교대가 읽었는지 재확인하는 곳. 사용자는 교대 직원, 구매·도입 결정자는 점주입니다. 직원이 근무 중 사용할 접근 수단도 있어야 합니다. A형 상황을 우선하고, 직원 순위가 구매 필수조건인 곳은 제외합니다.

먼저 확인할 가설은 다음 세 가지입니다.

- **H1 구매:** 점주가 직원 평가 없이 ‘인계 확인’에 실제로 지불하는가? → 동일 조건의 유료 제안과 입금·환불 기록으로 확인.
- **H2 자립 사용:** 근무 중 접근만으로 다음 교대가 확인하는가? → 운영자 알림 여부를 각 인계 기회와 함께 기록.
- **H3 제공 비용:** 온보딩 40분, 반복 지원 월 30분 안에 가능한가? → 가온이 점포별 실제 시간을 기록.

9월 14~20일 가온은 기존 시연 점주에게 최근 재확인 사례, 기존 채팅의 불편, 구매 권한, 접근 기기·직원 수용 여부를 묻고 곧바로 제안합니다. 추가 인터뷰 완료를 개발·판매의 선행조건으로 삼지 않습니다.

## 2. 첫 제공물과 범위

**D2 — 제안 O1:** 9월 28일~10월 11일, 점포당 **14일 14,500원**, 최대 5곳. 온보딩, 인계 기록·읽음 표시, 점주 날짜별 확인, 정해진 업무시간의 문의 지원을 포함합니다. 종료 후 월 29,000원은 별도 선택이며 자동 갱신하지 않습니다. 금액은 자료와 동일한 부가세 제외 기준입니다.

시작 전 취소는 전액 환불, 시작 후에는 남은 이용일을 일할 환불하는 조건을 제안합니다. 약속한 핵심 흐름을 제공하지 못한 기간도 환불에 반영합니다. 실제 청구·증빙 방법은 가온이 1주차에 확인하고, 결제 화면·외부 결제 연동은 제작하지 않습니다.

| 선택 | 이번 범위와 이유 |
|---|---|
| 우선 제작 | 모바일 웹 접근, 교대별 인계 작성·저장, 명시적 읽음, 점주 날짜별 확인, 미확인 상태, 수정·오류 복구, 최소 로그 |
| 수동 대안 | 같은 상태·역할 규칙을 갖춘 점포별 공유 문서와 가온의 온보딩. 개발 지연 시 동일 가격에 제공 방식을 명확히 안내 |

| 제외 | 다점포 권한, POS, 근무표·급여, 직원 성과 순위, 퇴근 후 개인 기기 확인 강제, 고객 얼굴·연락처 기록 |

일반 메모 도구로만 출시하면 기존 채팅·문서 대비 구매 이유가 약합니다. 반대로 관리 기능을 넓히면 개발·지원 시간이 초과됩니다. 점주 확인 화면과 읽음 의미를 우선하고, 자동화 범위를 줄입니다.

## 4. 소라에게 넘길 UX 요구

**D3 — 읽음은 다음 교대의 확인이며, 개인 신원 인증이나 업무 완료 증거가 아닙니다.** 점포 공유 접근으로 직원 개인 순위를 만들지 않습니다.

| 화면·흐름 | 요구와 수용 기준 |
|---|---|
| R1 점주 시작 | O1 가격·기간·환불·지원시간·제공 방식을 확인하고 도입. 가온이 점포·교대 이름과 접근 경로를 설정. 직원용 접근과 점주 설정 권한을 구분 |
| R2 직원 첫 진입 | 설치 없이 점포·현재/다음 교대를 확인. “읽음 ≠ 처리 완료”, 개인정보 금지 안내. 빈 화면은 ‘첫 인계 남기기’; ‘전달할 내용 없음’을 별도 선택하여 미작성과 구분 |
| R3 인계 작성 | 대상 교대 → 내용 → 저장. 성공은 서버 또는 공유 문서에 저장된 뒤 표시. 저장 실패 시 입력을 유지하고 재시도; 중복 제출로 항목이 늘지 않음 |
| R4 다음 교대 확인 | 출근 시 미확인 인계를 먼저 표시. 본문을 연 것만으로 읽음 처리하지 않고 ‘인계 내용을 읽었습니다’를 눌러 공유 상태 변경 |
| R5 점주 확인 | 날짜·교대별 미작성/미확인/읽음과 확인 시각 표시. 개인 성과 점수 없음. 다음 교대 종료 후 미확인은 근무 중 담당자에게 확인할 대상으로 남김 |
| R6 복구·종료 | 수정된 내용은 새 버전으로 다시 확인하고 이전 읽음은 이력으로 유지. 접근 만료·취소 시 재접속 안내. 퇴사·링크 노출 시 가온이 접근 경로 교체. 종료 시 기록 전달·삭제 일정을 점주에게 안내 |

점포를 잘못 연 경우 내용 입력 전에 돌아갈 수 있어야 합니다. 점주 확인 화면의 새로고침 후에도 저장·읽음 상태가 유지되고 다른 점포 기록이 보이지 않아야 합니다. 수동 대안도 이를 충족하지 못하면 모집을 축소합니다.

모바일 세로 화면, 명확한 버튼 이름, 색상 외 상태 문구, 키보드 조작·오류 안내를 요구합니다. 소라는 직원 역할 2명·점주 역할 1명에게 첫 작성 → 다음 교대 확인 → 미확인 찾기 과제를 제시합니다. 한 명이라도 읽음을 완료로 이해하면 문구·상태를 수정합니다. 이는 예정된 사용성 확인이며 완료된 검증이 아닙니다.

## 5. 사업모델과 경제성

출처: `input/costs-and-delivery.md`. 두 모델 모두 동일 타깃·기능이며 점주가 점포 단위로 지불합니다. 차이는 온보딩 비용 회수 시점입니다.

월 반복 지원비는 0.5시간×25,000원=12,500원, 첫 온보딩은 40/60시간×25,000원≈16,667원입니다.

**월 점포별 공헌액 = 요금×0.967 − 저장·알림 2,000원 − 지원 12,500원.**

| 비교 | A: 월 29,000원, 도입비 없음 | B: 도입비 29,000원＋월 19,000원 |
|---|---:|---:|
| 반복 월 공헌액/점포 | 13,543원 | 3,873원 |
| 5곳 반복 월 손익, 고정비 60,000원 차감 | 7,715원 | −40,635원 |
| 첫 달 5곳 손익, 온보딩·도입비 반영 | 약 −75,618원 | 약 16,247원 |
| 반복 월 고정비 손익분기 | 5곳 | 16곳 |

**A를 잠정 추천합니다.** B는 첫 달 회수가 좋지만 반복 손익분기 16곳은 지원 한도 5곳을 넘습니다. A도 지원이 월 60분이면 공헌액이 1,043원으로 줄어 5곳 손익은 −54,785원입니다. 획득비, 개발·디자인 유지비는 위 손익에서 제외되어 장기 수익성을 입증하지 못합니다.

O1은 A의 절반 기간·요금 실험입니다. 저장비·반복 지원을 절반으로 가정하면 첫 제공 공헌액은 점포당 약 **−9,895원**, 5곳과 월 고정비 포함 약 **−109,476원**입니다. 적자는 온보딩을 포함한 학습 비용입니다. 현금 수입과 인건비 환산 손익은 구분합니다.

지원 시간이 월 30분을 계속 넘거나 구매자가 월 29,000원을 거절하면 제공 범위·가격을 재검토합니다. B는 낮은 월요금 선호만으로 채택하지 않고, 지원 자동화 등으로 반복 경제성이 개선될 때 다시 비교합니다.
