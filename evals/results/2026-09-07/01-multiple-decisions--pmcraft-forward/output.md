GatherTrip 개발 전달 명세 초안: 여행 하나에서 숙소와 출발일을 따로 투표하고 주최자가 각각 확정한다. 개발자 1명·2주 MVP를 전제로 한다.

1. **근거와 결정**

   E1: [현재 요청](input/request.md). E2: [원본 방향](input/brief.md). 아래 핵심 요구의 근거는 이 두 문서다. 4–8명은 문서상 예상 규모다. 창업자가 선택한 방향이며 인터뷰·수요 검증·구현은 없다.

   D1(사용자 채택): E1·E2의 핵심 흐름·제외 범위를 유지한다. D2(제안): **[초안]** 정책은 누락 사항의 기본값이다. 로그인 없이 권한을 유지하기 위해 개인 복귀 링크를 제안한다. 링크 보유자가 권한을 가진다는 한계가 있다.

2. **객체와 관계 — R1, D1·D2**

   여행은 이름·주최자·공개 참가 링크를 가진다. 참가자는 여행에 속하며 닉네임·고유 ID를 가진다. 투표는 여행에 속하며 종류·선택지·마감 시각·상태·최종 선택지를 가진다. **[초안]** 여행당 숙소·출발일 투표를 하나씩 지원하며 동시에 열 수 있다.

   선택지는 특정 투표에만 속한다. 응답은 `(투표 ID, 참가자 ID)`마다 최대 1개이며 그 투표의 선택지만 가리킨다. 최종안은 응답과 별도다. 여행 전체에 하나의 응답·마감·최종안을 두지 않는다.

3. **생성·참가·권한 — R2, D1·D2**

   **[초안]** 여행 이름·닉네임으로 생성하면 주최자가 첫 참가자가 된다. 공개 링크에서 참가자 목록·투표 상태·득표수·최종안을 본다. 열람만으로 참가자가 늘지 않으며 닉네임 제출 성공 시 참가한다. 닉네임은 앞뒤 공백을 제거한 1–20자다. 여행 내 중복은 대소문자를 무시해 거절하고 다른 이름을 안내한다.

   **[초안]** 참가 시 추측하기 어려운 개인 복귀 링크를 발급하고 브라우저에서도 참가 상태를 기억한다. 다른 브라우저에서는 개인 링크로 복귀한다. 주최자는 별도 비공개 관리 링크를 받는다. 공개 링크나 닉네임만으로 기존 응답 수정·주최자 권한을 얻지 못한다. 주최자도 자기 응답만 바꾼다. 개인 링크의 저장·비공유를 안내한다. 브라우저 정보와 개인 링크를 모두 잃으면 권한 복구는 불가하다. 동일인의 중복 참가는 완전히 차단하지 못한다.

4. **투표 준비·진행·마감 — R3, D1·D2**

   **[초안]** 주최자가 종류별로 서로 다른 텍스트 선택지 2–5개와 미래 마감을 입력해 연다. 선택지는 공백만으로 구성할 수 없고 최대 100자다. 준비 중에는 수정 가능하며 참가자에게 보이지 않는다.

   상태는 `준비 → 진행 → 마감 → 확정`이다. 각 투표는 서버 시각으로 마감하며 한국 표준시(KST, UTC+9)를 표시한다. `현재 시각 < 마감 시각`에만 응답을 저장한다. 접속 여부와 무관하게 마감은 유효하다. 열린 뒤 선택지·마감 변경과 조기 마감·재개는 제외한다. 한 투표의 마감·확정은 다른 투표에 영향이 없다.

5. **응답·집계·미응답 — R4, D1·D2**

   참가자는 투표별로 하나를 선택하고 마감 전까지 교체한다. **[초안]** 응답 취소는 제외한다. 교체 시 이전 선택지는 −1표, 새 선택지는 +1표이며 총 응답자 수는 같다. 자기 선택은 보이고 타인의 선택 내역은 공개하지 않는다.

   투표별 득표수·응답자 수·참여 대상자 수·미응답 닉네임을 표시한다. **[초안]** 진행 중 대상자는 현재 참가자 전체이며 마감 후에는 마감 전에 참가한 사람으로 고정한다. 미응답자는 **해당 투표 대상자 중 해당 투표 응답이 없는 사람**이다. 숙소에만 답하면 출발일에서는 미응답이다. 늦은 참가는 허용하되 마감된 투표에는 ‘마감 후 참가’로 표시하고 집계에서 제외한다. 탈퇴·삭제는 제외한다.

6. **최종안·저장 실패 — R5·R6, D1·D2**

   **[초안]** 주최자는 마감 후 기존 선택지를 확인해 확정한다. 최다 득표가 아니거나 동률·응답 0명이어도 선택 가능하다. 자동 확정은 없다. 확정 전에는 ‘마감 · 주최자 확정 대기’, 이후에는 최종안과 기존 득표수를 표시한다. 번복 불가를 확인 단계에서 안내한다.

   참가·응답·확정은 서버 저장 성공 후 완료를 표시하고 새로고침에도 유지한다. 실패하면 입력을 보존하고 재시도한다. 통신 단절로 결과가 불명확하면 서버 상태를 재조회한다. 반복 제출로 참가자·응답이 중복되지 않는다. 여러 탭에서는 서버가 마지막으로 수락한 응답만 남는다. 서버 처리 시각이 마감 이상이면 변경을 거절하고 저장된 응답·마감 상태를 보여준다. 확정 반복·다른 선택 재확정은 최초 확정안을 유지하며 보여준다. 타인 화면은 진입·새로고침 시 갱신하며 실시간 통신은 제외한다.

7. **인수 조건 — 모두 계획됨, 미실행·결과 미관찰**

   향후 구현을 검증하며 실행 시 환경·버전을 기록한다. 아래는 합성 시나리오다.

   | 검증 | 연결 | 조건·행동 → 관찰 결과 |
   |---|---|---|
   | V1 | R1·R3 | 숙소·출발일을 동시에 열고 숙소만 마감 → 출발일 응답은 계속 가능 |
   | V2 | R2 | 공개 링크 열람 → 인원 불변; 닉네임 참가 재시도 → 한 명만 추가; 개인 링크로 다른 브라우저 복귀 → 동일 참가자 |
   | V3 | R2·R5 | 공개 링크 방문자가 주최자 확정이나 타인 응답 수정을 요청 → 거절, 기존 데이터 유지 |
   | V4 | R4 | 민수는 숙소만 응답, 지수는 모두 미응답 → 숙소 미응답은 지수, 출발일 미응답은 둘; 마감 후 참가자는 해당 투표 집계에서 제외 |
   | V5 | R4·R6 | 민수가 숙소 A에서 B로 변경·반복 저장 → A −1, B +1, 총 응답자 불변; 새로고침·다른 참가자 화면에서도 동일 |
   | V6 | R3·R6 | 마감 직전 저장 성공 후 마감 시각에 변경 요청 → 기존 응답 유지·변경 거절; 실패·통신 단절 후 재시도 → 중복 없이 서버 결과 확인 |
   | V7 | R5·R6 | 동률 또는 응답 0명인 마감 투표를 주최자가 확정 → 전원에게 최종안 표시; 반복·다른 선택 재확정 → 최초 확정 유지 |

8. **2주 범위와 다음 행동**

   여행 생성부터 공유·참가·두 투표 응답·수정·개별 마감·확정·결과 확인까지 포함한다. 계정·결제·예약 연동·채팅·알림은 원본대로 제외하며 추가 투표 종류·운영 관리 기능도 미룬다.

   **[초안]** 1주차는 생성·권한·참가·투표·응답, 2주차는 마감·확정·복구·검증에 배분한다. 일정은 추정 전 가정이다. 개발자가 권한 유지와 저장·마감 경계의 작업량을 먼저 산정하고 초과하면 범위를 재조정한다. 두 투표의 독립성과 저장·복구는 유지한다. 명세는 구현·검증 완료나 출시 준비를 입증하지 않는다.
