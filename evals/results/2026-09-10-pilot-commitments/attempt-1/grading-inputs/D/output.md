# 마감잇 첫 유료 실험 실행·디자인 인계안

**잠정 추천: 직원 12명 이하 단일 카페에 ‘근무 중 작성 → 다음 교대 읽음 → 점주 확인’을 제공한다.** 앱 개발보다 이 흐름에 점주가 돈을 내는지 먼저 확인한다. 준비·검증 기간은 **2026년 9월 14일~10월 11일**, 유료 서비스는 **9월 21일~10월 4일의 14일**로 한정한다.

모든 근거는 제공된 **합성 자료**다. 아래 가격·범위·판정 기준은 제안이며 실제 고객 수요나 실행 결과가 아니다.

## 1. 리서치 판단과 첫 타깃

| 자료와 관찰 | 판단 및 실행 연결 |
|---|---|
| `research-records.md`, 8/18~25: 4개 카페의 6명. A 점주는 부재중 읽음 확인을 원하고 직원은 중복 작성·퇴근 후 응답을 거부 | 점주가 부재하는 교대가 있고, 직원이 근무 중 기존 메모를 대체할 수 있는 점포부터 모집 |
| 8/26~9/8: 무료 수동 사용 3곳, 인계 기회 42회·메모 28회·읽음 20회·직접 알림 16회 | 작성 이후 확인까지 이어지는 흐름을 측정. 알림과 사용의 교차 집계가 없어 자발적 사용이라고 해석할 수 없음 |
| A는 계속 사용 희망, B는 채팅 복귀, C는 점주 화면 요구 | A와 유사한 상황을 우선하되 B의 무료 채팅 선호를 반증으로 유지. C의 직원 순위 요구는 범위 밖 |
| 9/9: B 직원이 읽음과 완료를 혼동 | ‘읽었어요’를 명시하고 작업 완료와 분리 |
| 실제 유료 고객 0곳 | 가격 수용·유지율·누락 감소·시간 절약은 미검증 |

기존 대안은 종이, 채팅, 공유 문서다. 무료이고 익숙하지만 A 사례에서는 중복 기록이 관찰됐다. 마감잇의 차별 가설은 **한 번 남긴 인계를 다음 교대가 확인했는지 날짜별로 보여주는 것**이다. 시장 전체의 문제라고 일반화하지 않는다.

**첫 타깃:** 단일 점포, 직원 12명 이하, 교대가 반복되고 점주가 모든 교대를 직접 보지 못하는 카페. 점주가 구매·도입을 결정하고 직원은 근무 중 사용한다. 직원 평가나 퇴근 후 확인을 요구하는 점포는 제외한다.

9/14~18 가온이 실제 최근 교대 사례로 확인할 질문:

- 기존 채팅·종이 중 무엇을 마감잇으로 대체할 수 있는가?
- 다음 교대가 읽음을 표시할 근무 시간과 기기는 있는가?
- 점주는 읽음 확인에 14일 29,000원을 지불하는가?
- 온보딩·마무리 확인에 언제 참여할 수 있는가?

답변만 모으지 않고 실제 양식 작성과 가격이 명시된 신청까지 연결한다.

## 2. 하나의 제공물과 일정

**제안 상품:** 점포당 29,000원, 14일 일회성 유료 실험. 직원 12명까지, 인계 양식·읽음 표시·점주 날짜별 조회·40분 온보딩·정해진 시간의 문의 지원을 포함한다. 앱 설치는 필요 없다. 자동 갱신과 자동 알림은 없다.

공유 문서와 수동 지원으로 제공할 수 있음을 결제 전에 알린다. 개발 완료가 판매 조건은 아니지만, 접근 제한과 저장·읽음 구분이 가능한 제공 수단은 필수다.

| 기간 | 담당·시간 상한 | 순서와 완료물 |
|---|---|---|
| 9/14~20 | 가온 10h, 도윤 10h, 소라 5h | 타깃 확인 → 모바일 시안·직원 과제 확인 → 제공 수단 점검 → 조건 제시·신청. 9/18 모집 마감 |
| 9/21~27 | 가온 10h, 도윤 12h, 소라 3h | 9/21 근무 중 온보딩 후 시작. 최대 5곳의 작성·읽음·지원시간 기록. 오류와 문구 수정 |
| 9/28~10/4 | 가온 10h, 도윤 6h | 동일 조건으로 반복 사용 관찰. 10/4 서비스 종료, 이후 신규 작성 중단 |
| 10/5~11 | 가온 10h | 10/5까지 마지막 문의 처리, 10/6 결과 전달, 10/8 점주 검토, 10/9 정정·종료 처리 |

총 상한은 가온 40h, 도윤 28h, 소라 8h다. 가온은 첫 주 모집·검증 8h와 여유 2h, 둘째 주 온보딩 4h·지원 3h·기록 2h·여유 1h를 배정한다. 셋째 주 지원 3h·관찰 4h·여유 3h, 마지막 주 종료·정산 6h·여유 4h다.

지원 창구는 월·수·금 12~13시(KST), 다음 지원 창구까지 답변하는 안이다. 9/18까지 고객의 온보딩·검토 가능 시간을 확인한다. 마무리까지 일정이 맞지 않으면 이번 모집에서 제외하며 뒤늦은 시작은 받지 않는다. 10/9까지 해결하지 못한 공급자 측 문제는 해당 점포를 전액 환불하고 종료한다.

**보류:** 다점포, POS·외부 연동, 근무표·급여, 직원 평가, 작업 완료 관리, 자동 알림, 앱 설치, 정식 결제 화면. 모집 기준 미달이어도 이미 결제한 고객의 약속은 이행한다.

## 3. 마케팅과 작은 검증 실험

**소개 문구**

> 다음 교대가 읽었는지, 점주도 확인하세요.  
> 마감잇은 근무 중 남긴 인계를 다음 교대가 ‘읽었어요’로 확인하는 서비스입니다. 직원 12명 이하 단일 카페 대상, 9/21~10/4 14일간 점포당 29,000원. 최대 5곳에 공유 문서 또는 간단한 웹과 수동 지원을 제공합니다. 자동 갱신·퇴근 후 확인 요청은 없습니다.

**행동 유도:** “우리 매장 참여 조건과 일정을 확인하기”

가온이 9/14~18에 기존 시연 점주 3명에게 후속 제안을 하고, 지인에게 신규 점주 최대 5명의 소개를 요청한다. 소개 가능성은 고객 확보로 세지 않는다. 준비물은 위 문구, 화면 예시, 일정·가격·환불 조건 한 장이다.

대안 채널은 지역 커뮤니티다. 운영진의 초안 허용 후에만 게시한다. 회원 63명을 노출 수로 간주하지 않는다. 직원 영상 계정은 구매자 비중을 몰라 이번 주력에서 제외한다.

**실험 기록과 잠정 판정**

| 단계 | 무엇을 세는가 | 다음 행동 |
|---|---|---|
| 모집, 9/14~18 | 적격 점주 중 전체 조건을 확인한 수, 신청 수, 실제 결제 수. 채널별 가온 기록 | 조건 확인 5곳 이상 중 결제 2곳 이상이면 실험 진행. 0~1곳이면 신규 모집 중단하고 가격·문제 적합성 수정 |
| 첫 가치 | 결제 점포 중 첫 2회의 인계 기회 안에 작성→다음 교대 읽음→점주 조회를 마친 점포 수 | 실패 점포는 접근·의미 혼동을 수정하고 원인 기록 |
| 반복 사용, 9/21~10/4 | 점포별 예정 인계 기회, 메모 기회, 읽음 기회, 점주 조회일, 직접 알림 여부·지원 분 | 최소 2곳에서 주당 3회 이상 기회가 있고, 두 주 모두 기회 절반 이상 읽음 확인이면 후속 제안 검토 |

조회했다고 읽음으로 자동 집계하지 않는다. 알림 유무를 각 기회와 함께 기록하되 인과효과라고 주장하지 않는다. 적격 노출 부족, 휴점·교대 부재, 기록 누락은 부정적 수요와 구분해 **판단 유보**한다.

10/6~9에는 다음 달 월 29,000원 조건에 대한 의사를 묻되, 후속 인력 확보 전에는 결제받지 않는다. 재구매 의향은 유지율이 아니다.

## 4. 디자이너·개발자 인계

핵심 객체는 **점포, 근무자 접근권한, 교대 인계 묶음, 메모 버전, 읽음 기록**이다.

| 화면·역할 | 요구와 상태 |
|---|---|
| 참여·결제 전 / 점주 | 대상 조건 → 14일 가격·제공 방식 → 지원·종료·환불 조건 → 일정 확인 → 신청 순서. 가온이 정원·일정을 확인한 뒤 결제 안내 |
| 첫 진입 / 직원 | 점포명·근무자 선택/확인, “근무 중 사용”, “읽음은 처리 완료가 아닙니다” 표시. 빈 화면에 첫 인계 작성 유도 |
| 인계 작성 / 직원 | 다음 교대, 내용 필수. 저장 중·저장 완료·실패를 구분. 실패 시 내용 보존 후 재시도. 중복 제출은 한 건으로 처리 |
| 다음 교대 / 직원 | 미확인 인계 우선, 본문 다음에 ‘읽었어요’. 읽음 주체·시각 표시. 열람만으로 상태 변경 금지 |
| 날짜별 조회 / 점주 | 메모 없음·미확인·확인을 구분. 직원 순위와 완료율 없음 |
| 미인계·종료 | 예상 교대 시각 이후 미확인 안내. 점주가 근무 중 대면 확인하거나 다음 지원 창구에 요청. 퇴근자에게 강제 알림 금지. 종료 후 쓰기 중단과 결과 수령 경로 표시 |

**권한·변경 규칙:** 점주가 직원 접근을 승인·회수한다. 링크 보유만으로 점주 권한을 주지 않는다. 직원은 자기 메모를 수정하고 읽음은 본인만 남긴다. 본문 수정은 새 버전으로 표시하며 이전 읽음은 과거 버전에 남고 재확인이 필요하다. 퇴사자 접근을 회수해도 과거 기록은 유지한다. 고객 얼굴·연락처 입력은 금지한다.

모바일에서 본문과 주 행동을 먼저 보이고, 명시적 레이블·키보드 접근·색 외 상태 문구를 제공한다. 소라는 직원에게 “인계 작성, 다음 교대 확인, 읽음과 완료 차이 설명”을 요청해 도움 없이 가능한지 관찰한다.

**예정 인수 시나리오:** 저장 실패 후 재시도해도 메모 한 건만 남는다. 열람만 하면 미확인이다. 읽음 후 본문 수정 시 재확인이 표시된다. 회수된 직원은 접근하지 못한다. 미확인은 작업 미완료로 표시되지 않는다. 모든 시나리오는 계획이며 실행 통과 기록은 없다.

## 5. 사업모델·예산·추천을 뒤집을 조건

두 모델 모두 점주가 점포 단위로 비용을 내고 같은 인계·조회 기능을 받는다.

| 월 운영 가정 | A: 월 29,000원 | B: 도입비 20,000원 + 월 19,000원 |
|---|---:|---:|
| 반복 월 점포별 공헌액 | 13,543원 | 3,873원 |
| 온보딩 포함 첫 달 공헌액 | −3,124원 | 6,546원 |
| 5곳 반복 월, 고정비 차감 후 | 7,715원 | −40,635원 |
| 5곳 첫 달, 고정비 차감 후 | −75,618원 | −27,268원 |
| 반복 월 고정비 회수 필요 점포 | 5곳 | 16곳 |

계산은 `costs-and-delivery.md` 기준이다. 공헌액은 가격×0.967−저장·알림 2,000−지원 12,500원. 첫 달에는 온보딩 40분×25,000원/시간을 차감하며 B는 도입비의 수수료 차감액을 더한다. 전체 손익은 고정비 60,000원을 추가 차감했다.

**A 잠정 추천:** B는 초기 비용 회수에 유리하지만 반복 손익분기점이 지원 한도 5곳을 넘는다. A도 지원이 월 60분이면 점포 공헌액이 1,043원으로 줄어든다. 획득비·장기 개발 유지비 전 수치이므로 안정적 이익이라고 볼 수 없다.

이번 **14일 29,000원은 월 구독과 다른 일회성 제안**이다. 월 비용 일할 계산은 확인되지 않았다. 9~10월 두 달 청구 가능성을 보수적으로 잡으면 저장·알림 4,000원, 지원 환산 25,000원, 온보딩을 반영한 점포 공헌액은 −17,624원, 5곳·고정비 120,000원 포함은 −208,118원이다. 학습 비용으로 제한한다. 가온이 9/18 전 실제 청구 단위를 확인한다.

현금 800,000원 배분: 도구 120,000원(기존 예약 100,000원 포함), 점포 비용 20,000원, 결제 수수료 5,000원, 모집 100,000원, 비구매조건부 과제 사례비 120,000원, 소재 30,000원, 환불·돌발 예비비 150,000원, 미배정 255,000원. 실제 5곳 결제 수수료는 4,785원이다. 매출로 예산을 늘리지 않는다.

획득비는 모집 현금과 모집시간 환산액을 **같은 실제 유료 점포 수**로 나눠 기록한다. 결제 0곳이면 산출 불가다. 지원 과다, 반복 사용 부진, A 가격 거절이 이어지면 확장을 멈추고 제공 범위·가격을 다시 정한다. 기존 고객은 약속대로 종료 지원 또는 환불한다.

산술은 입력값을 이용한 계산 도구 결과와 대조했고 원 단위로 반올림했다. 고객 연락·게시·결제·제품 실행·파일 변경은 수행하지 않았다.
