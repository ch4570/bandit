**ShelfNote 첫 배포 추천 및 개발 인계안 — 2026-09-09**

**D1·추천:** 창고 1곳의 주간 직원 12명과 현 교대 책임자를 대상으로, ‘텍스트 제보 → 책임자 확인·현장 조치 → 처리 기록 → 직원의 결과 확인’을 배포한다.

근거 E1은 [brief.md](input/brief.md)의 채택 방향·작업환경·견적이다. 직원이 비공개 시트의 상태를 볼 수 없어 재문의한다는 설정을 해결한다. 자료는 합성 입력이며 실제 수요나 효과를 입증하지 않는다. [draft.md](input/draft.md)의 9월 6일 화면들은 미채택 제안이다. 지도 중심 홈·공유 피드 대신 역할별 목록을 진입점으로 삼는다.

범위와 일정은 다음과 같다.

- 유지: 기존 로그인·직원 디렉터리·선반 조회·공유 저장소·모바일 폼. 텍스트 제보/내 제보 1.5일 + 책임자 목록/처리 1일 + 흐름 점검 0.5일 = **3 개발일**. 4일 중 1일은 보완 여유이며 출시 보장은 아니다.
- 보류: 사진, 오프라인 전송, 이메일, 지도, 대시보드, 배정·기한·댓글·수정 이력. 이메일만 추가해도 4일을 모두 써서 보완 여유가 없어진다.
- 제외: 긴급상황, 재고 수량, 구매, 장비 정비, 공개 링크, 신규 가입.
- 대안: 기존 메시지·시트는 개발 없이 유지할 수 있으나 직원의 직접 결과 확인을 충족하지 못한다. 접수만 만드는 축소안도 같은 이유로 권하지 않는다.

아래 R1–R5는 D1의 구현 명세다. 자료에 없는 길이·정렬·재시도·수정 정책은 **추천 기본값**이다.

- **R1·제보 객체/권한:** 창고, 제보 ID, 선반 ID, 설명, 작성자 직원 ID, 서버 접수시각, 상태, 처리 메모·처리자·처리시각을 저장한다. 활성 직원은 생성과 자기 제보 조회만, 현 책임자는 창고 전체 조회와 처리 기록을 할 수 있다. 서버가 매 요청에서 재직·역할·소유권을 검사한다. 교대 후 새 책임자가 기존 건을 이어받으며 과거 처리자 기록은 유지한다. 퇴사자는 접근할 수 없다.
- **R2·접수:** 직원이 디렉터리의 유효 선반을 선택하고 공백 제외 1–1,000자 설명을 입력한다. 선반 ID·통로명을 보여 오선택을 확인하게 한다. 서버 저장 성공 후에만 제보 ID와 ‘접수’를 표시하고 내 제보에 추가한다. 잘못된 선반·빈 설명은 저장하지 않고 해당 입력을 안내한다.
- **R3·연결 복구:** 전송 중 중복 탭을 막는다. 실패·응답 유실 때 입력과 제출 식별자를 유지하고 ‘저장 여부 확인 필요’를 표시한다. 연결 복구 후 동일 식별자로 재시도하면 이미 저장된 같은 건을 반환하거나 한 번만 생성한다. 성공 확인 전 새 식별자로 재전송하지 않는다. 자동 오프라인 큐는 없다.
- **R4·처리:** 책임자 목록은 미처리 건을 오래된 순으로 표시한다. 상세에서 선반·설명·작성자·접수시각을 확인하고 기존 창고 업무로 교정한다. 실제 조치 후 1–1,000자 처리 메모와 명시적 ‘처리 완료’ 동작으로만 접수→처리 완료가 된다. 열람은 상태를 바꾸지 않는다. 메모·처리자·시각·상태는 함께 저장한다. 중복 또는 오래된 완료 요청은 최초 기록을 덮어쓰지 않고 현재 결과를 보여준다. 실패하면 입력을 보존하고 재확인·재시도한다.
- **R5·결과 확인:** 내 제보는 최신 접수순이며 선반·상태를 표시한다. 상세에 원문과 처리 메모·처리시각을 제공한다. 재진입/새로고침으로 서버 상태를 읽는다. 빈 목록은 ‘제보 없음’, 조회 실패는 오류와 재시도를 보여 구별한다. 저장 후 수정·삭제·재개는 제공하지 않는다. 잘못된 내용이나 재발은 원본 ID를 적은 새 제보로 남긴다. 앱은 물리적 교정을 검증하지 않는다.

**V1·예정 인수 확인:** 첫 후보 빌드의 창고용 휴대폰 브라우저와 공유 저장소에서 직원·책임자가 반나절 동안 R1–R5를 확인한다. 유효/무효 입력, 저장 후 재접속, 응답 유실 후 재시도 시 단일 건, 열람 후 접수 유지, 완료 후 직원에게 동일 메모 표시, 완료 충돌 시 최초 기록 유지, 타인 제보 직접 접근 차단, 책임자 교체·퇴사자 차단, 빈 목록·조회 실패를 점검한다. 빌드·기기·결과를 기록한다. 현재 구현·실행·통과 증거는 없다.

가장 큰 미확인은 기존 저장소의 중복 방지·일괄 저장과 동적 권한 지원이다. 개발자는 이를 먼저 확인해 재견적한다. 필수 복구와 점검·수정이 4일을 넘으면 완결 흐름을 유지하며 첫 사용을 늦춘다. 시범 사용에서 설명만으로 선반 문제를 판단하기 어려운 사례가 확인되면 사진 보류를 재검토한다.
