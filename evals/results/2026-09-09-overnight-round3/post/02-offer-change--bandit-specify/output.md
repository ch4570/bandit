기준일: 2026-09-09  
상태: 다음 파일럿의 채택 방향과 구현용 제안. 구현·검증 완료를 의미하지 않는다.

## 1. 목적과 현재 결정

프리랜서가 변경 견적을 팀 동료와 작성하고, 지정 고객 담당자에게 해당 버전의 명시적 결정을 받는다.

- **D2 채택:** 다음 파일럿부터 건당 결제를 없애고 무료로 제공한다. 기존 D1을 대체한다.
- **D3 채택:** 같은 팀 동료가 링크를 통해 견적 초안을 함께 작성한다.
- **유지:** 고객 승인·거절 권한은 지정 고객 담당자에게만 있다. 열람은 승인이 아니며, 변경된 조건에는 새로운 결정이 필요하다.

**추천:** 무료·팀 협업 방향으로 다음 파일럿을 진행하되, 목표는 견적 발송과 기회가 있는 사용자의 반복 사용 검증으로 둔다. 현재 자료는 가격 효과, 협업 효과, 유료 수요 또는 소프트웨어 협업 안정성을 입증하지 않는다.

범위는 초안 공동 작성, 버전 발송, 고객 결정, 결과 확인과 실패 복구다. 결제·구독, 공동 고객 승인, 실시간 동시 타이핑은 제외한다.

## 2. 역할·객체·권한

견적은 생성자, 초대된 팀 동료, 지정 고객 담당자와 연결된다. 발송 버전은 금액·통화·납기·견적 내용을 고정한 기록이며 고객 결정은 담당자와 버전에 귀속된다.

아래 세부 권한·충돌·복구 규칙은 사용자 결정의 실행을 위한 **제안 기본값**이다.

| 역할 | 허용 행동 |
|---|---|
| 생성자 | 초안 작성·수정, 동료 초대·접근 회수, 고객 담당자 지정, 발송, 모든 버전과 결정 확인 |
| 초대된 팀 동료 | 해당 견적과 발송 이력 열람, 현재 초안 수정. 발송·초대 관리·고객 결정 불가 |
| 지정 고객 담당자 | 고객용으로 발송된 버전 열람, 현재 결정 가능한 버전에 승인 또는 거절 |
| 그 외 링크 소지자 | 편집·고객 결정 불가 |

초대는 생성자가 지정한 동료 신원과 연결한다. 링크만으로 팀 소속이나 권한을 인정하지 않으며, 초안·결정 행동 전에 초대 또는 담당자 신원을 확인한다. 구체적인 인증 방식은 구현에서 선택한다.

접근 회수는 열린 화면에도 적용한다. 회수된 동료의 후속 열람·저장은 거절하고, 기존 저장 내용과 작성 이력은 유지한다.

## 3. 현재 요구사항과 흐름

**R1 개정 — 공동 초안:** 생성자가 초안을 만들고 동료를 초대한다. 초대받은 동료는 신원 확인 후 공동 작성한다. 저장 성공 여부와 최신 내용을 표시한다. 같은 기준본에서 경쟁 저장이 발생하면 먼저 저장된 내용을 유지하고, 뒤의 저장은 충돌로 알린다. 덮어쓰지 않고 미저장 입력을 보존하여 최신본 확인·재적용을 지원한다.

**R4 대체 — 무료 발송:** 생성자는 금액·통화·납기·고객 담당자를 확인하고 “무료로 견적 보내기”를 실행한다. 결제 화면, 결제 상태 확인, 미결제 발송 차단은 없다. 동료가 발송 직전 초안을 변경했다면 생성자가 최신 내용을 다시 확인해야 한다. 발송 시 고정 버전과 고객 링크를 만든다. 전달 실패를 표시하고 같은 버전으로 재시도할 수 있으며 중복 버전을 만들지 않는다.

**R2 유지 — 명시적 결정:** 고객 링크 열람은 열람 기록만 남긴다. 지정 담당자가 승인 또는 거절을 제출해야 결정 상태가 바뀐다. 저장된 결정과 대상 조건을 고객·생성자에게 표시한다. 동일 요청의 재시도는 중복 결정이 되지 않는다. 저장 실패 시 완료로 표시하지 않고 재시도를 제공한다.

**R3 유지·구체화 — 버전:** 발송된 조건은 직접 수정하지 않는다. 금액이나 납기 변경은 새 초안·새 발송 버전을 요구한다. **제안:** 그 밖의 고객 제시 조건 변경도 동일하게 취급한다. 새 초안 작성만으로 이전 결정은 바뀌지 않는다. 새 버전 발송 시 이전 미결정 버전의 결정 접수는 닫는다. 이전 승인·거절은 원래 버전에 남고, 새 버전으로 승계되지 않는다. 기존 승인은 기존 조건의 기록으로 유지되며 새 조건은 별도 승인을 기다린다.

오래된 링크에서 결정하면 저장을 거절하고 최신 버전으로 안내한다. 개정 발송과 고객 결정이 경합하면 먼저 확정된 상태에 따라 처리하며, 실제 결정된 버전을 명확히 보여준다. 이미 결정된 버전의 결정 변경은 허용하지 않고 새 버전으로 처리한다.

## 4. 원래 기록과 근거의 적용 범위

**D1 대체됨:** 프리랜서가 견적당 9,000원을 선결제하는 일회성 요금이었다. 구독이 아니었다.  
**H1 역사적 가정:** 월 10건 × 9,000원 = 활성 프리랜서당 월 총매출 90,000원, 비용·환불 전. 월 10건 사용은 검증되지 않았고 무료 파일럿 수익 예측에 사용할 수 없다.

| 공급된 관측 | 해석·처리 |
|---|---|
| 8월 유료: 8명 각 1건 구매·사용, 2명 전액 환불, 보고일에 6명 결제 유지 | 결제액 72,000원, 환불 18,000원, 환불 후 잔존 수납액 54,000원으로 계산된다. 이익은 알 수 없다. 기존 가격의 역사적 증거다. |
| 8월: 30일 내 8명 모두 후속 기회, 2명 재사용 | 기회 보유자 재사용 2/8=25%. 월 10건 가정을 뒷받침하지 않는다. |
| 9월: 24명 가입·앱 열람, 14명 발송 | 무료·협업·공개 커뮤니티 모집이 결합된 조건에서 발송 14/24=58.3%. 결제 요청이 없어 지불 의사는 미관측이다. |
| 9월: 경과 10일, 발송자 중 후속 기회 6명, 재사용 4명 | 기회 보유자 기준 4/6=66.7%. 나머지 발송자 8명은 아직 기회가 없고, 미발송자 10명의 기회 여부는 미수집이다. 모두를 재사용 실패로 계산하지 않는다. |

9월에는 창업자의 직업적 인맥에서 공개 커뮤니티로 모집도 확대됐고 무작위 배정이 없었다. 관측 기간도 달라 8월 대비 상승을 가격이나 협업의 인과 효과로 해석할 수 없다. 협업은 수동 컨시어지 방식이었으며 소프트웨어 충돌 처리는 관측되지 않았다.

## 5. 다음 실험·열린 결정

**X1 역사적 기록:** 30일 유료 제안에서 수납·전달·환불·반복 사용을 관측하는 실험이었다. 보편적 통과 기준은 채택되지 않았다.

**X2 제안:** 다음 무료·팀 협업 파일럿은 참여자별 30일 관측을 완료한다. 모집 경로, 최초·후속 견적 기회, 발송, 고객 결정, 동료 참여, 충돌·복구와 수동 개입을 기록한다. 기회 없음·미수집·기회 후 미사용을 분리하고 비율에 분모를 병기한다.

기회가 있는 사용자의 발송·재사용이 이어지고 협업 복구가 가능하면 방향을 유지한다. 미사용이 반복되면 원인을 확인해 흐름을 수정하거나 대상을 좁힌다. 권한 침해나 저장 유실이 발생하면 해당 협업 경로를 보완한다. 비교 가능한 조건과 충분한 관측 없이 단일 요소의 효과를 주장하지 않는다.

열린 결정은 장기 수익 모델과 수치형 진행 기준이다. 모두 미채택이며 무료 파일럿 명세를 막지 않는다.

## 6. 검증 상태와 수용 시나리오

- **V1:** 공급 기록상 v1 스테이징의 명시적 승인·거절 전이가 2026-08-10 통과했다(R2/R3). 당시 결과는 유지하되 새 권한·버전 경합 조건은 재검증이 필요하다.
- **V2:** 같은 날짜 v1 미결제 발송 차단 통과는 역사적 결과다. 무료 발송의 성공 증거가 아니다.
- **V3:** 동시 초안 편집은 기존에 미구현·미검증이며, 컨시어지 관측으로 검증되지 않는다.

다음은 모두 **계획된 확인이며 실행 결과는 미관측**이다.

1. 미결제 생성자가 유효 초안을 보내면 결제 없이 고정 버전·고객 링크가 생성된다.
2. 초대 동료는 초안을 저장하지만 외부 링크 소지자·접근 회수자는 저장할 수 없다.
3. 두 동료가 같은 기준본을 수정하면 두 번째 저장에 충돌이 표시되고 입력과 선행 저장이 보존된다.
4. 고객 링크 열람 후에는 미결정이며, 지정 담당자의 명시적 제출만 해당 버전을 승인·거절한다.
5. 승인 후 금액·납기를 바꿔 발송하면 이전 승인은 이전 버전에 남고 새 버전은 미결정이다.
6. 오래된 결정·중복 제출·전달 실패 재시도에서 잘못된 승인 승계나 중복 버전 없이 결과와 복구 방법이 표시된다.
