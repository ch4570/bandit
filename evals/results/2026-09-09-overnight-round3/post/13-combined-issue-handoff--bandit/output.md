**첫 배포는 ‘문자 제보 → 책임자 처리 기록 → 직원의 결과 확인’으로 추천합니다(D1).** 대상은 한 창고의 직원 12명과 현재 교대 책임자입니다. 아래 세부 정책은 개발 인계를 위한 추천 초안입니다.

근거 E1은 `input/brief.md`의 2026-09-09 채택 방향·작업 조건·추정치입니다. 직원이 기존 비공개 시트에서 상태를 볼 수 없다는 설정이 이 범위의 이유입니다. 자료는 모두 합성 입력이며 실제 고객 검증이나 구현 증거가 아닙니다. E2인 `input/draft.md`는 미채택 화면 제안이므로 지도 중심 구성을 제보와 처리 중심으로 대체합니다.

**범위와 일정**

- 유지: 기존 로그인·직원 디렉터리·선반 조회·공유 저장소, 문자 제보와 내 제보, 책임자 대기 목록과 처리 기록.
- 계산: 제보·내 제보 1.5일 + 책임자 처리 1일 + 현장 점검 0.5일 = 3일. 남은 1일은 재시도 보장과 수정 여유로 둡니다. 추가 작업이 이 안에 들어가는지는 미검증이며 배포일 확약이 아닙니다.
- 보류: 사진, 오프라인 큐, 이메일, 지도, 대시보드, 배정·기한·댓글·편집 이력. 사진만 추가해도 점검 포함 4.5일입니다.
- 제외: 긴급 상황, 재고 수량·구매·설비 관리, 공개 링크, 신규 가입.
- 대안인 기존 메시지·시트 유지는 개발 부담이 작지만 직원의 직접 결과 확인을 충족하지 못합니다. 핵심 흐름이 4일을 넘으면 이를 임시 유지하고 첫 사용을 늦춥니다.

**개발 명세 — 모두 D1에 연결**

**R1. 제보 객체와 권한.** 제보는 창고, 고유 번호, 선반 ID, 설명, 제보자 ID, 생성 시각, 상태, 처리 내용·처리자 ID·처리 시각을 저장합니다. 상태는 `미처리 → 처리 완료`뿐입니다. 활성 직원은 생성과 자기 제보 조회, 현재 책임자는 창고 전체 조회와 완료 기록이 가능합니다. 서버에서 매 요청마다 권한을 확인합니다. 퇴사자는 접근할 수 없으며 기록은 유지합니다. 책임자 교체 시 대기 목록은 새 책임자에게 이어집니다.

**R2. 생성.** 직원은 기존 조회로 유효한 선반을 선택하고 설명을 입력한 뒤 제출합니다. 설명은 공백 제외 필수, 최대 1,000자로 제안합니다. 제출 전 선반·내용을 확인하고 수정할 수 있습니다. 서버 저장 확인 후에만 번호와 `미처리`를 표시하며 내 제보에 나타납니다. 유효하지 않은 선반이나 저장 실패는 입력을 유지하고 수정·재시도를 안내합니다.

**R3. 연결 끊김과 중복.** 응답이 없으면 성공으로 표시하지 않고 ‘저장 여부 확인 필요’를 표시합니다. 연결 복구 후 동일 제출 식별자로 확인·재시도하여, 이미 저장됐다면 기존 번호를 반환합니다. 연속 탭도 한 건만 생성합니다. 자동 오프라인 전송은 하지 않습니다.

**R4. 처리.** 책임자는 오래된 미처리 순 목록에서 상세를 열고 기존 현장 업무로 실물을 바로잡습니다. 열람만으로 상태는 바뀌지 않습니다. 실제 조치 후 필수 처리 내용(최대 1,000자)을 입력하고 완료를 명시적으로 저장합니다. 상태와 처리 기록은 함께 저장됩니다. 실패하면 미처리로 남고 입력을 보존합니다. 이미 완료된 건에 대한 재시도·경합은 기존 결과를 반환하며 덮어쓰지 않습니다. 앱은 물리적 조치를 검증하지 않습니다.

**R5. 결과 확인.** 직원은 내 제보 목록과 상세에서 현재 상태, 완료 시 처리 내용·시각을 봅니다. 재접속·새로고침하면 저장된 최신 결과를 가져옵니다. 조회 실패는 빈 목록과 구분하고 재시도를 제공합니다. 저장 후 수정·삭제·재개는 보류하며 추가 문제는 새 제보로 제출합니다.

**인수 확인과 다음 행동**

V1–V5는 각각 R1–R5의 **계획된 확인이며 미실행·결과 미관측**입니다. 작업용 휴대폰 두 대와 시험 계정으로 다음을 확인합니다.

- 타인 제보 접근 차단, 퇴사자 차단, 책임자 교체 후 처리 가능.
- 정상 제출 후 재로그인해도 같은 번호·내용 유지.
- 저장 직후 응답 유실과 반복 탭에도 한 건만 존재.
- 열람은 미처리 유지, 완료 저장 실패·경합에서 기록 보존.
- 책임자 완료 후 직원이 새로고침하여 동일 처리 결과 확인.

개발자는 먼저 공유 저장소의 중복 방지·권한·원자적 완료 저장 가능성을 확인하고 재추정합니다. 이후 확보된 반일에 전체 흐름을 점검합니다. 직원이 직접 결과를 확인해 재문의가 줄어드는지는 첫 사용에서 확인할 가설입니다.
