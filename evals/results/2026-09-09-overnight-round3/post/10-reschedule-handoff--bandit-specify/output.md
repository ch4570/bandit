Slotlet 일정 변경 개발 인계 명세

현재 요구사항의 기준은 채택된 `input/booking-policy.md`와 사용자 요청이다. **새 시간 확정과 기존 시간 해제가 함께 성공하기 전까지 원래 확정 예약을 유지한다.** 미승인 `input/draft.md`의 선취소, 브라우저 타이머 기준 승인, 오류 시 무조건 처음부터 재시작하는 흐름은 폐기한다.

1. **범위와 권한**

   기존 로그인·예약 조회·일반 취소를 이용한다. 예약은 인증된 고객 한 명, 스튜디오 한 곳, 60분 슬롯에 속한다. 소유자만 일정 변경을 요청할 수 있고 서버가 소유권과 예약 상태를 검증한다. 같은 스튜디오의 겹치는 시간에 확정 예약을 중복 생성하지 않는다.

   이번 범위는 같은 스튜디오 내 시간 변경이다. 성공 시 기존 선결제 이용권을 대체 예약으로 승계한다. 결제·환불·반복 예약·캘린더 연동·새 계정 체계는 제외한다.

2. **진입과 후보 선택**

   예약 상세에서 현재 확정 시간과 ‘시간 변경’을 제공한다. 변경 가능 여부는 기존 예약 시작 시각과 서버 시각으로 판단한다. **추천 초안:** 시작까지 정확히 24시간 남은 시점은 허용하고, 그보다 짧으면 차단한다. 홀드 생성과 최종 확정 때 모두 재검증하므로 홀드가 변경 가능 기한을 연장하지 않는다.

   후보 조회만으로는 자리를 점유하지 않는다. 선택 시 서버가 이용 가능 여부를 다시 확인하고 성공한 경우에만 2분 홀드를 만든다. 다른 고객에게는 해당 스튜디오의 홀드와 겹치는 시간이 선택 불가로 표시된다. 오래된 목록에서 선택해도 서버가 거절한다. 현재 예약과 같은 시간은 변경 대상으로 제공하지 않는 것을 추천한다.

3. **홀드와 복수 탭**

   홀드는 원래 예약, 소유자, 대상 슬롯, 만료 시각, 변경 시도에 연결된다. 상태는 활성·만료·해제·사용 완료로 구분한다. 모든 사용자 표시 시각에 날짜와 `Asia/Seoul`을 명시하고, 카운트다운은 참고 정보로만 사용한다.

   **추천 초안:** 원래 예약 하나당 활성 홀드는 하나만 허용한다. 다른 탭에서 새 후보 선택에 성공하면 이전 홀드를 함께 해제하고 새 시도로 교체한다. 새 후보 확보에 실패하면 기존 활성 홀드는 유지한다. 이전 탭의 확정은 거절하고 최신 예약·홀드 상태를 보여준다.

   **추천 초안:** 서버 시각이 만료 시각보다 작은 동안만 홀드가 유효하다. 정확히 만료 시각부터 기존 홀드로 확정할 수 없고 다른 고객이 확보할 수 있다. 홀드 포기·만료는 원래 예약을 바꾸지 않는다.

4. **확정과 경쟁 처리**

   확정은 고객이 선택한 대상, 해당 홀드와 원래 예약의 상태 버전에만 적용한다. 서버는 소유권, 변경 기한, 활성 홀드, 최신 예약 상태, 대상 수용 가능 여부를 확인한다.

   성공하면 새 슬롯 확정·기존 슬롯 해제·이용권 승계를 하나의 결과로 반영하고 홀드를 사용 완료 처리한다. 일부만 반영된 상태를 허용하지 않는다. 실패하면 기존 확정 예약을 유지한다.

   **추천 초안:** 변경·일반 취소·다른 탭의 변경이 경쟁하면 먼저 완료된 결과만 유효하다. 이후 오래된 상태를 전제로 한 요청은 거절하고 최신 상태를 안내한다. 명시적 일반 취소가 먼저 완료됐다면 취소 상태를 유지하며 일정 변경으로 예약을 되살리지 않는다.

5. **응답 유실과 복구**

   동일 변경 시도의 반복 확정은 한 번만 반영하고 같은 처리 결과를 반환한다. 응답이 끊기면 성공이나 실패로 단정하지 않고 ‘결과 확인 중’과 조회 재시도를 제공한다. 예약 상세 재진입에서도 서버의 실제 확정 예약을 발견할 수 있어야 한다.

   조회 결과 성공이면 새 시간을, 미완료·실패이면 기존 시간과 홀드 상태를 표시한다. 홀드가 유효하면 같은 시도를 재확인할 수 있고, 만료됐다면 후보를 다시 선택한다. 서버 확인 전에는 ‘변경 완료’를 표시하지 않는다.

6. **수용 시나리오 — 계획됨, 실행 결과 없음**

   - 소유자·타인 및 24시간 경계 전후에서 조회·홀드·확정을 시도하면 권한과 서버 기준 기한에 맞게 허용·거절된다.
   - 후보를 둘러보거나 홀드 후 포기해도 원래 예약은 유지된다. 정상 확정 후에는 새 예약과 이용권만 유효하고 기존 시간이 풀린다.
   - 두 고객이 겹치는 대상을 동시에 확보하면 하나만 성공한다. 활성 홀드는 타 고객을 차단하고 정확한 만료 시각에는 이전 고객의 확정을 거절한다.
   - 배경 탭의 카운트다운이 남아 있어도 서버상 만료됐다면 확정을 거절하고 기존 예약을 표시한다.
   - 두 탭에서 후보를 바꾸면 최신 홀드만 확정 가능하다. 오래된 확정·취소 경쟁 요청은 최신 결과를 덮어쓰지 않는다.
   - 확정 처리 실패 시 기존 예약이 남는다. 성공 직후 응답 유실·반복 클릭·재접속에도 중복 예약이나 이용권 중복 없이 실제 결과를 조회한다.

7. **근거와 전달 조건**

   `input/support-notes.md`는 클릭 화면을 이용한 합성 워크스루다. 복수 탭, 재확정, 타이머, 만료 경쟁의 미정 동작을 보여주지만 실제 장애나 검증 결과는 아니다. 기존 초안에는 구현·테스트가 없다.

   개발자 1명·5일은 목표이며 확정 공수가 아니다. 기존 취소 연동, 예약 전환의 일괄 반영, 반복 요청 처리와 결과 조회 지원 여부를 먼저 확인해야 한다. 추천 초안은 채택 정책과 구분되며, 기술 확인 결과에 따라 일정 재산정이 필요하다. 파일 수정·구현·제품 테스트는 수행하지 않았다.
