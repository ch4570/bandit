# Slotlet 일정 변경 개발 인계 명세

기준: `input/request.md`, 채택된 `input/booking-policy.md`. 아래 ‘추천’은 위임받은 미정 규칙의 제안이며 채택된 정책과 구분한다.

**목표와 범위**

새 시간 확정과 기존 시간 해제가 함께 성공하기 전까지 원래 확정 예약을 보존한다. 기존 로그인·예약 조회·일반 취소를 재사용하며, 소유 고객의 동일 스튜디오 내 60분 슬롯 변경을 제공한다. 성공 시 기존 선불 이용권을 대체 예약에 이전한다. 결제·환불·반복 예약·캘린더 동기화·새 계정 시스템은 제외한다.

**객체와 상태**

- 예약: 소유 고객, 스튜디오, 60분 구간, 현재 상태를 가진다. 동일 스튜디오의 겹치는 시간에 확정 예약을 중복 생성할 수 없다.
- 홀드: 원래 예약 상태, 소유자, 목표 슬롯, 서버 만료 시각에 연결된다. 활성 → 사용 완료·만료·해제 중 하나로 전이한다. 활성 홀드는 다른 고객의 해당 스튜디오·시간 점유를 막는다.
- 변경 시도: 특정 원래 예약 상태와 홀드에 묶인다. 결과는 성공 또는 거절이며, 응답 유실은 고객에게 결과 미확인으로 표시한다. 미확인을 실패로 단정하지 않는다.

**현재 만들 동작**

1. 로그인한 예약 소유자만 변경을 요청한다. 서버 시간으로 기존 예약 시작 24시간 전까지 가능하다. 화면 진입뿐 아니라 홀드 생성과 확정 시 권한·예약 상태·기한을 재검사한다.
2. 빈 목표 시간을 탐색할 때는 홀드를 만들지 않는다. 선택 시 서버가 실제 가용성을 확인하고 2분 홀드를 만든다. 경합에서 지면 ‘선택한 시간이 마감되었습니다’를 표시하고 다시 선택하게 한다. 원래 예약은 유지한다.
3. 목표 시간과 만료 시각을 표시한다. 사용자에게 전달하는 시각에는 날짜와 Asia/Seoul을 명시한다. 카운트다운은 참고용이며 서버가 만료를 판정한다. 화면 복귀 시 상태를 다시 조회한다.
4. 확정은 소유권, 변경 기한, 원래 예약 상태, 연결된 활성 홀드, 목표 시간 점유를 모두 만족해야 한다. 새 슬롯 확정·기존 슬롯 해제·이용권 이전은 함께 성공하거나 모두 적용되지 않는다. 성공 확인 후에만 ‘변경 완료’와 현재 예약을 보여준다.
5. 홀드 만료·변경 실패는 원래 예약을 취소하지 않는다. 만료 시 재선택을 제공한다. 네트워크 오류에는 ‘결과를 확인 중입니다’와 재조회·재시도를 제공한다. 예약 상세를 다시 열어도 서버의 실제 현재 확정 예약을 찾을 수 있어야 한다.

**추천 세부 규칙**

- 예약 하나당 활성 홀드 하나를 허용한다. 다른 탭에서 새 목표 홀드 확보에 성공하면 이전 홀드를 함께 해제한다. 확보 실패 시 이전 홀드는 기존 만료 시각까지 유지한다. 같은 선택 재요청은 만료를 연장하지 않는다. 탭별 용량 분리를 막고 불필요한 점유를 줄인다.
- 서버 판정 시각이 홀드 만료 시각보다 작을 때만 확정 가능하다. 같으면 만료되어 다른 고객이 확보할 수 있다. 24시간 제한은 정확히 경계까지 허용하며 홀드가 제한 시간을 연장하지 않는다.
- 확정 재시도는 같은 시도 식별자를 사용하고 이미 처리한 결과를 반환한다. 성공 응답이 유실되어도 추가 예약이나 이용권 이전을 만들지 않는다.
- 교체된 홀드나 오래된 예약 상태의 확정은 거절하고 현재 예약·홀드를 조회하도록 안내한다. 최신 상태에 오래된 확정 의사를 자동 적용하지 않는다.
- 일반 취소와 변경이 경합하면 하나만 유효하게 완료한다. 취소가 먼저면 변경을 거절하고 홀드를 해제한다. 변경이 먼저면 이전 상태 대상 취소를 거절한다. 명시적 일반 취소로 취소된 예약은 변경 실패 시 복원하지 않는다.

**초안 변경과 근거**

미승인 `input/draft.md`의 선취소, 브라우저 타이머 기반 승인, 오류 시 처음부터 시작을 위 동작으로 교체한다. `input/support-notes.md`는 가상 클릭 화면 walkthrough다. Hana의 두 탭 확정 버튼, Joon의 재시도 질문, Mina의 실제 경과와 다른 8초 표시, 관리자의 만료 순간 경합 질문은 아래 검증 설계의 근거다. 실제 고객 사고나 제품 테스트 결과가 아니다.

**수용 시나리오 — 모두 계획, 실행 결과 없음**

- 정상 변경: 유효 홀드를 확정하면 새 예약만 확정되고 기존 슬롯은 가용해지며 이용권은 한 번 이전된다.
- 비소유자 또는 변경 기한 초과: 홀드·확정을 거절하고 예약을 바꾸지 않는다. 정확한 24시간 경계에서도 추천 규칙대로 판정한다.
- 탐색·경합: 탐색만 하면 타 고객 가용성이 유지된다. 같은 목표를 동시에 선택하면 하나만 홀드를 얻고, 활성 홀드 중 타 고객의 겹치는 예약 확정은 불가능하다.
- 만료: 화면에 8초가 남아도 서버 만료 시각 이상이면 확정을 거절하고 원래 예약을 유지한다. 만료 순간 타 고객 확보와 경합해도 중복 확정은 없다.
- 두 탭: A 홀드 후 B의 새 홀드가 성공하면 A 확정은 거절된다. B 성공 후 오래된 탭에서도 현재 예약을 조회할 수 있다.
- 저장 실패·응답 유실: 전환 실패면 원래 예약과 이용권이 유지된다. 서버 성공 후 응답만 유실되면 재조회·동일 시도 재전송이 같은 성공 결과를 보여준다.
- 취소 경합: 어느 작업이 먼저 완료되든 위 추천 규칙대로 단일 결과를 보여주며 예약을 중복 생성하거나 되살리지 않는다.

**일정과 미확정 사항**

개발자 1명, 목표 5일이다. 기존 취소 서비스와 원자적 변경·재시도·현재 예약 조회의 연동 공수는 미측정이다. 착수 시 이를 확인해 일정 가능성을 재산정한다. 구현 방식은 개발자에게 열어두며 핵심 예약 보존·복구·경합 검증은 일정 때문에 생략하지 않는다. 추가 사용자 결정 없이 위 추천으로 설계를 진행할 수 있으나, 추천은 채택된 정책으로 기록하지 않는다. 구현·제품 테스트·파일 수정은 수행하지 않았다.
