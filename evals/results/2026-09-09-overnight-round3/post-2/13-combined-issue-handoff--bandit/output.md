사진·오프라인 큐·이메일·지도·대시보드·배정·기한·댓글·편집 이력은 보류한다. 긴급상황·재고 수량·구매·장비 정비·공개 링크·신규 가입은 제외한다.

R1 — 제보 객체와 권한(D1)  
제보는 창고, 고유 번호, 선반 ID, 설명, 제보자 직원 ID, 서버 접수 시각, 상태, 해결 내용·담당자 ID·시각을 가진다. 상태는 ‘미해결 → 해결’뿐이다. 활성 직원은 생성과 본인 제보 조회만, 현재 책임자는 해당 창고 전체 조회와 해결 기록이 가능하다. 서버가 매 요청에 현재 자격을 확인한다. 교대 시 새 책임자가 기존 미해결 건을 이어받으며, 이전 책임자는 일반 직원 권한으로 돌아간다. 퇴사자는 접근 불가지만 기존 기록은 유지한다.

R2 — 직원 제보와 복구(D1)  
로그인 후 ‘내 제보’에서 새 제보를 연다. 기존 조회로 유효한 선반을 선택하고 문제 설명을 입력한다. 설명은 공백 제외 필수, 최대 1,000자다. 저장 시 선반 유효성을 재확인하며 오류는 해당 입력 옆에 표시하고 입력을 유지한다. 저장 확정 후에만 제보 번호와 ‘미해결’을 표시한다.

연속 탭·응답 유실 후 재시도는 동일 제출 식별자로 처리하여 같은 제보 하나와 번호를 반환한다. 결과 불명 시 성공/실패로 단정하지 않고 ‘저장 확인 필요’를 표시한다. 현재 폼과 식별자를 유지하고 연결 복귀 후 같은 요청을 재시도한다. 서버 확정 실패는 입력 수정 후 재전송 가능하다. 오프라인 자동 제출은 없다.

R3 — 책임자 처리와 직원 확인(D1)  
책임자는 오래된 순의 미해결 목록에서 상세를 열고 기존 창고 업무로 물리적 수정을 조율한다. 열람은 상태를 바꾸지 않는다. 수정 후 필수 해결 내용(최대 1,000자)을 쓰고 ‘해결 기록’을 눌러야 내용·담당자·시각·상태가 함께 저장된다. 소프트웨어는 현장 수정을 검증하지 않는다. 중복 요청은 한 번만 반영하고, 이미 해결된 건의 다른 요청은 덮어쓰지 않고 저장된 결과를 보여준다. 저장 실패/결과 불명 시 내용을 유지하고 재조회·재시도를 제공한다.

직원은 최신 접수순 ‘내 제보’와 상세에서 현재 상태, 해결 내용·시각을 확인한다. 목록 진입·새로고침 시 서버 상태를 읽는다. 빈 목록과 조회 실패를 구분하고 실패에는 재시도를 제공한다. 이번에는 제출 후 수정·삭제·재개방을 제공하지 않는다. 잘못된 제보는 책임자에게 기존 메시지로 정정을 전달하며 실제 수정 없이 해결 처리하지 않는다.

V1–V3 — 예정된 인수 확인  
업무용 휴대폰 브라우저와 공유 저장소를 연결한 후보 빌드에서 다음을 확인한다. 실행 시 빌드·환경·결과를 기록한다.

- V1→R1: 다른 직원의 번호로 조회가 거부되고, 교대 후 새 책임자는 기존 건을 처리하며 퇴사자는 접근하지 못한다.
- V2→R2: 유효하지 않은 선반/빈 설명은 저장되지 않는다. 저장 직후 응답을 끊고 재시도해도 한 건만 남으며 재로그인 후 같은 번호가 보인다.
- V3→R3: 열람만으로 미해결이 유지된다. 해결 저장 후 직원이 새로고침하면 동일 내용이 보이며 동시 해결 요청이 기록을 덮어쓰지 않는다.

다음 행동: 개발자가 저장소의 중복 방지·원자적 해결 지원과 추가 공수를 먼저 확인한다. 4일 초과가 예상되면 핵심 복구를 빼지 말고 첫 사용일을 재조정한다. 이후 책임자 참여 반일 워크스루에서 위 흐름을 확인한다. 구현·제품 테스트·현장 검증은 아직 수행되지 않았다.
