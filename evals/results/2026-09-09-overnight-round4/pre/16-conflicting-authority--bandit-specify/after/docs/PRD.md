# TeamSlate 작업보드 PRD

합성 평가용 프로젝트. 문서, 인물, 정책과 실행 기록은 모두 가상이다.
문서 상태: v2 개발 인계 초안. 제품 책임자: 윤서.

## 1. 제품과 객체

TeamSlate는 조직 구성원이 작업과 댓글을 공유하는 내부 작업보드다.
작업과 댓글은 각각 고유 ID, 소속 조직 ID, 작성자 ID, 작성 시각을 가진다.
조직은 공유 콘텐츠의 소유 주체이며 작성자의 개인 계정과는 구별한다.

## 2. 기존 공통 동작

R-01: 현재 조직 구성원은 그 조직의 작업과 댓글을 읽는다. 작성자만
자신의 작업 본문을 편집하고, 작업 담당자는 상태를 진행 중 또는 완료로
바꾼다. 댓글 내용은 작성 후 편집하지 않는다.

R-02: 조직 A의 구성원 자격만으로 조직 B의 콘텐츠를 읽을 수 없다.
작업 완료는 삭제가 아니며 완료된 작업에도 기존 댓글이 남는다.

## 3. 조직 탈퇴 흐름

근거: [멤버십 탈퇴 정책](../policy/membership-departure.md)의 M-01~03과
[기여 기록 정책](../policy/contribution-records.md)의 C-01~02는 일치한다.
R-03~05는 이 채택 규칙을 구체화한다.

R-03: 현재 구성원은 조직 설정에서 자신의 탈퇴를 요청한다. 대상 조직,
접근 종료, 기록 보존, 계정·다른 조직 자격 유지를 확인하고 명시적으로 확정한다.
확정 전 취소하면 자격은 유지된다. 타인의 탈퇴는 범위 밖이다.
이름 표시는 D-01 결정 전 단정하지 않는다.

R-04: 완료 시 대상 조직의 구성원 자격이 종료된다. 이후 새 조회·작성·변경을
거부한다. 이미 열린 화면의 저장도 현재 자격을 검사하여 거부하고 권한 상실을
알린다. 저장 성공으로 표시하지 않는다. 계정·다른 조직 자격은 유지한다.

R-05: 기존 작업·댓글은 조직 소유로 남는다. 본문·상태·작성자 ID·작성 시각을
변경·삭제·재귀속하지 않는다. 남은 구성원의 권한은 R-01~02를 따른다.

R-06 — 제안된 복구 기본안: 확인 전, 처리 중, 완료, 실패/결과 확인 필요를
구분한다. 처리 중 중복 확정을 막고 완료 후 조직 밖으로 안내한다.
확인된 실패는 재시도한다. 응답 유실 시 자격을 재확인하여 이미 탈퇴했으면
완료로 안내하고, 구성원이면 재시도하게 한다. 미확인 결과를 성공으로 표시하지 않는다.
반복 요청은 콘텐츠·다른 조직 자격을 바꾸지 않는다. 이는 정책에 없는 제안이다.

D-01 — 열린 결정: M-04 정책의 M-04는 남은 구성원의 작업 상세·활동 이력에서
탈퇴자의 기존 작업·댓글 작성자 이름을 `탈퇴한 멤버`로 대체하고 작성 당시
이름을 숨기도록 요구한다. C-09 정책의 C-03은 같은 화면에서 작성 당시
이름을 그대로 표시하도록 요구한다. 동일한 v2 자체 탈퇴에 적용되는 두 정책은
모두 윤서·수민이 승인했다. 늦은 채택일만으로 C-09가 M-04를 대체했다고
판단하지 않는다. 승인자 윤서·수민이 어느 규칙을 대체할지 결정해야 한다.
이름 표시 구현·검증은 결정 대기다. 접근 차단·기록 보존은 독립적으로 진행 가능하다.

## 4. 탈퇴 수용 기준

모두 계획이며 실행 결과는 없다. R-06 기준은 제안, D-01 기준은 결정 대기다.

- A-01 / R-03: A 구성원이 탈퇴를 요청하면 대상·영향을 확인한다.
  취소하면 자격을 유지하고 명시적 확정 후 완료되면 A 자격이 끝난다.
- A-02 / R-04: 완료 사용자의 A 작업·댓글 새 조회·작성·변경을 거부한다.
  탈퇴 전 열린 화면의 본문 저장·담당 작업 상태 변경도 거부하며 기존 값을
  유지하고 권한 상실을 표시한다.
- A-03 / R-04~05: A/B 구성원이 A를 탈퇴해도 계정·B 자격은 유지된다.
  남은 A 구성원은 기존 작업·댓글을 읽으며 본문·상태·작성자 ID·작성 시각은
  탈퇴 전과 같다. R-01의 권한 제한도 유지된다.
- A-04 / R-06: 중복 확정, 실패 후 재시도, 완료 응답 유실에서 현재 자격에
  맞는 결과·복구 경로를 제공한다. 콘텐츠를 중복 변경하거나 미확인 결과를 성공으로 표시하지 않는다.
- A-05 / D-01: 결정 후 작업 상세·활동 이력의 기존 작업·댓글 작성자 이름이
  선택된 규칙과 일치하는지 확인한다. 현재 기대 표시값은 미확정이다.

V-01은 해당 조건의 조직 격리 근거로 유지한다. V-02는 수동 제외 후 새 조회
거부에 한정된 과거 통과다. 자체 탈퇴·열린 화면 저장·이름 표시의 통과로
재사용하지 않는다. 위 시나리오는 별도 검증이 필요하다.

## 5. 기존 실행 기록

V-01 — 2026-08-20, v1.8 스테이징, 합성 조직 A/B: A 구성원의 B 작업
직접 주소 조회 2건이 거부되어 통과했다. 운영 환경은 검사하지 않았다.

V-02 — 2026-08-21, v1.8 스테이징: 운영자가 콘솔에서 구성원 한 명을
수동 제외한 뒤 그 사용자의 새 작업 조회 요청 1건이 거부되어 통과했다.
이미 열린 화면에서의 저장, 사용자 자체 탈퇴, 기여자 이름 표시는 검사하지 않았다.

## 6. 이번 배포 밖

내보내기, 조직 간 작업 이동, 댓글 편집, 계정 전체 삭제, 재가입 흐름은
이번 범위 밖이다. 별도 디자인 시스템이나 로그인 서비스를 만들지 않는다.
